## 1. 项目概览

### 1.1 它解决什么问题

服务器是动态公网地址，没法做固定 IP 白名单；而把 1Panel（40001）、雷池 WAF 面板（16002）直接暴露到公网，等于把管理后台敞开。

本工具通过 SSH 本地端口转发，把这些面板「搬」到本机 `127.0.0.1` 上：面板端口对外保持关闭，只有隧道可达，浏览器访问零感知。

### 1.2 组成与运行形态

| 组成 | 说明 |
| --- | --- |
| `sgtunnel.py` | 单文件 GUI 程序（tkinter，暗色主题，约 1,728 行） |
| `assets\app.ico` / `app.png` | 图标源：`app.ico` 供 exe 文件图标（构建期内嵌）+ 备用窗口图标；**窗口标题栏图标已于 2026-11-06 按要求彻底移除（标题栏左侧无图标）**，`app.png` 现仅作备用 |
| `assets\sponsor_qr.png` | 赞助收款二维码，界面右侧卡片展示 |
| `config.json` | 唯一参数来源，与 exe 同目录 |
| `server_key` | SSH 私钥，与 exe 同目录 |
| `dist\爽哥面板隧道助手.exe` | PyInstaller 单文件发行物（约 11.15 MB） |

运行形态：**单文件 exe + 同目录 config.json（+ 可选 server_key）**，无安装、无注册表、无第三方运行时依赖，资源全部内嵌，不需要随包附带 `assets` 目录。

### 1.4 现实问题与应对

| 问题 | 具体表现 | 本工具的应对 |
| --- | --- | --- |
| 服务器公网 IP 动态变化 | 安全组/防火墙白名单无法固定，改一次 IP 就要改一次规则 | 不做 IP 白名单，改由 SSH 鉴权（私钥或密码）控制访问 |
| 管理面板端口不宜暴露公网 | 1Panel、雷池面板直接 `0.0.0.0` 监听等于把后台敞开，易被爆破 | 面板端口仅监听服务器回环（`127.0.0.1`），公网不可达 |
| 手动敲 ssh 命令易错 | 参数长、端口多、每次切面板都要改命令 | 参数全部落盘到 `config.json`，界面点选即切换 |
| 私钥权限问题频发 | 拷贝私钥后 ACL 过宽，OpenSSH 报 `Bad permissions` 拒绝加载 | 启动隧道前自动调用 `icacls` 收紧权限 |
| 部分服务器只开密码认证 | 无密钥可用时工具完全失效（v2.0 限制） | v2.1 新增密码认证；v2.2 起密码用 Windows DPAPI 加密存于 `password_enc`，重启自动解密回填，明文永不落盘 |

解决思路是最朴素的一种：**用 SSH 通道把远端回环端口"搬"到本地回环端口**。远端面板只认 `127.0.0.1:远程端口`，本地用户访问 `127.0.0.1:本地端口`，流量经 SSH 加密通道抵达服务器后再从服务器本地回环出去。对面板自身而言，请求来源永远是本机，因此无需任何面板侧改造，也无需在面板上开公网监听。

### 1.6 它不是什么（非目标，避免误判）

- **不是 VPN / 不是代理服务器**：没有全局流量接管，只做端口级转发，一个面板一条转发。
- **不是远程桌面或 Web 面板替代品**：不代管面板账号、不做登录态中转。
- **不内置 SSH 协议栈**：不 `import paramiko`，不管理 `known_hosts`。v2.1 虽支持密码认证，但**不是自己实现认证协议** —— 仍旧调用系统 `ssh.exe`，通过 `SSH_ASKPASS` 机制递交口令，认证协议由 OpenSSH 完成。
- **不是凭据管理器**：v2.2 虽用 DPAPI 加密持久化密码，但那是"单用户本机便捷快照"，不做多用户分发、不做主密钥口令保护、不支持导出迁移。要求"多人共享凭据"的需求超出本项目定位（边界见 8.1.2.8）。
- **不是跨平台工具**：界面用 tkinter 可跨平台跑，但 `_fix_key_permission` 依赖 `icacls`、askpass 脚本是 `.cmd` + PowerShell、`CREATE_NO_WINDOW` 是 Windows 标志，实际只在 Windows 上验证与发布。

### 1.7 版本增量详解（v2.0 → V2.3）

> **【口径】** 其中 1.7.5 / 1.7.6 的 v2.4、v2.5 是**图标迭代期的内部标号**，最终归档进 `V2.3`（`APP_VER` 始终为 `2.3`），不是对外发布版本号；保留细目是为了不丢失图标方案的实现参数与验收证据。

> 1.3 是速览表，本节是逐版细节。其中 **v2.4 / v2.5 是图标迭代期的内部标号**，最终形态已归档进 `V2.3` 口径（`APP_VER` 现为 `2.3`），见 0.1 第 5 条。

#### 1.7.1 v2.0 相对 v1.x 的增量

按 README 的版本历史与代码实际形态核对，v2.0 的三项实质增量是：

1. **单面板 → 多面板数组**：配置从顶层 `local_port` / `remote_port` 两字段改为 `panels[]` 数组 + `current` 当前项，下拉框可切换。旧格式通过 `load_config` 的回退分支自动升格，不会因缺字段崩溃。
2. **端口联动 + 纯名称显示**：切换面板会带出该面板的端口；下拉框标签只显示 `name`，不再拼接端口（`_resolve_panel_name` 仍保留对旧式 `名字 (端口)` 标签的兼容解析）。
3. **密钥权限自修复**：新增 `_fix_key_permission`，在 `start_tunnel` 中先于 `Popen` 执行，用 `icacls` 去掉继承权限并只授予当前用户读权限。
#### 1.7.2 v2.1 相对 v2.0 的增量

v2.1 是一次**配置能力 + 稳定性**升级，四项实质变化：

1. **配置项全覆盖语义**：界面支持逐项编辑 `SSH 端口` / `用户名` / `密钥文件` / `密码` / `本地端口` / `远程端口`，并把"认证方式"提为显式单选（新增 `config.json` 字段 `auth_method`，取值 `key` / `password`，缺省 `key`）。
2. **"空即空"加载规则**：删除 `_ensure_default_config` 自举模板与 `panels` 端口兜底 `40001`。`config.json` 中字段为空字符串 / `null` / 缺失时，对应输入框**保持留空**，不注入任何默认值或模板值。
3. **密码安全边界**：密码只在内存与 `ssh` 子进程环境变量中存在，**不写入 `config.json`、不出现在命令行参数**；读配置时若发现残留 `password` 字段会忽略并提示；`key_path` 位于程序同目录时保存只写裸文件名，整包搬动仍可用。
4. **稳定性修复**：端口非数字不再让监控线程静默死亡（`_parse_port` + 启动前校验 + 可见报错）；`stop_tunnel` 的 `wait` 超时被捕获；后台线程改为经队列与界面交互（`queue` + `after`）；关窗补上进程清理；版本号收为 `APP_NAME` / `APP_VER` 常量，标题不再三处硬编码。

### 2.4 来源目录实况与 BASE_DIR 判定

`sgtunnel.py` 中的 `BASE_DIR` 判定决定了"程序认为的家目录"在哪：冻结态（PyInstaller 打包后 `sys.frozen` 为真）取 `os.path.dirname(sys.executable)`，即 **exe 所在目录**；源码态取脚本所在目录。`CONFIG_PATH` 恒为 `BASE_DIR/config.json`。

### 2.5 dist 与源目录的差异含义

> **【现状（2026-11-06）】** `dist\` 目录已随本轮清理移入回收站，本节描述的是**当时的构建现场**，重新打包后仍需按本节第 1、2 条重新核验 `key_path`。

`dist/config.json` 的 `key_path` 指向 `E:\yscl\sgtunnel\dist\server_key` —— 注意其中 `sgtunnel` 一段：当前项目目录已改名为 `爽哥面板隧道助手`，说明这份 `dist/config.json` 是**在改名/迁移之前的构建现场生成的残留**，且被程序记录成了绝对路径。

这带来两个直接后果：

1. **可移植性断裂**：把 `dist` 整体拷到别的机器或别的盘符，`key_path` 依然指向 `E:\yscl\sgtunnel\dist\server_key`，`start_tunnel` 的存在性校验会直接弹"密钥缺失"。
2. **相对路径自动升级的例外**：`load_config` 只对"不含路径分隔符且非绝对路径"的 `key_path` 做 `BASE_DIR` 拼接。绝对路径原样保留，不会被纠正回当前目录。

> **v2.1 的改观**：`_collect_config` 已实现"密钥在程序同目录时只写裸文件名"，所以在 exe 里点一次**保存配置**，就能把 `dist/config.json` 的 `key_path` 自动收敛回 `server_key`。存量错误路径不会自动改写，需要一次人工保存（见 8.1.3 第 4 条）。

> **结论**：分发前必须把 `key_path` 改回裸文件名 `server_key`，或干脆不随包分发 `config.json`。注意 v2.1 已取消"首启自举"：**不存在 `config.json` 时程序照常启动，但所有输入框都是空的**，由使用者自己填写后保存 —— 这正是"加载 config.json 时字段为空则留空"这条需求的必然结果，不要再指望程序替你生成模板。

### 2.6 为什么配置与私钥必须与 exe 同目录（不能打进 exe）

| 约束 | 原因 |
| --- | --- |
| 两份 spec 的 `datas` **只含赞助二维码与图标**（v2.5 未变） | v2.0–v2.2 为 `[]`；v2.3 起为 `[(assets\sponsor_qr.png, 'assets')]`；v2.4 起为 `[(sponsor_qr.png, 'assets'), (app.ico, 'assets'), (app.png, 'assets')]`，**没有任何配置/密钥进包**。所以 exe 内部仍不存在 `config.json` / `server_key`，"三件套同目录"规则不变 |
| 配置需要可编辑 | 用户/维护者要能直接改 IP、端口、面板列表；打进 exe 后每次改配置都得重新打包 |
| 配置需要可写 | `save_config` 与 `_auto_save` 直接对 `CONFIG_PATH` 覆盖写。若资源在 exe 内部（onefile 解压目录）则写入会随进程退出而丢弃 |
| 私钥不该进包 | 私钥进 exe 等于把凭据固化成可分发二进制，任何人拿到 exe 即可提取。当前设计让它以独立文件存在，便于单独管控与随时替换 |
| 源码态与冻结态路径统一 | `BASE_DIR` 两分支都指向"程序文件所在目录"，使"把三件套放同一目录"这条规则在两种运行方式下都成立 |

### 2.7 运行期最小文件集

```

├── 爽哥面板隧道助手.exe   ← 必须有
├── config.json            ← 可选（缺失则界面全空，需人工填写后保存）
└── server_key             ← 按需：密钥认证必须有；密码认证可不放
```

只缺 `config.json` 时程序仍可启动，但不会生成任何模板：`load_config` 检测到文件不存在（或解析失败）时只写一条日志，随后所有输入框保持**空白**（`server` / `ssh_port` / `user` / `key_path` / `local_port` / `remote_port` 全空，认证方式回到默认的"密钥认证"，面板列表仅剩一个名为 `面板1` 的空壳）。

> **v2.3 补充**：`assets\sponsor_qr.png` 是**唯一"可缺"的运行时资源**。打包态由 exe 内嵌（`_MEIPASS`）提供，不依赖外部目录；源码态缺 `assets\sponsor_qr.png` 时，赞助卡片退化为纯文字（只记一条日志），程序其他一切功能不受影响。

> **v2.4 补充（v2.5 沿用）**：`assets\app.ico` / `assets\app.png` 同样是"可缺"资源，用途仅限外观。打包态由 exe 内嵌提供，窗口图标走 `_MEIPASS\assets\`；绿色分发态可把 `assets\` 放在 exe 同级（`asset_path` 第二档命中）。两者都缺时窗口沿用 Tk 默认图标、只写一条日志，**不影响任何功能**。注意 exe 的**文件图标**（资源管理器里看到的那个）是构建期由 spec 的 `icon=` 写进 PE 资源的，与运行时 `assets\` 是否存在无关 —— 想换文件图标必须重新打包。

> v2.0 的行为是 `_ensure_default_config` 写出一份含 `22022` / `root` / `server_key` / `40001` 的模板；**v2.1 已按需求删除该函数**。差异直接影响首次使用：v2.1 必须自己填全再保存，否则点"启动隧道"会被 `_validate` 拦下并弹出"请填写服务器地址/请填写用户名/端口必须为 1-65535 的数字"等聚合提示。
>
> 这不只是"引导填写"，而是配置语义的收紧：**空值就是空值，程序不再替使用者做任何猜测**。好处是不会出现"明明没配却连上了某个历史服务器"，代价是首次使用必须完整填一遍。

### 2.10 外部硬依赖

#### 2.10.1 OpenSSH 客户端（强制）

程序通过 `subprocess.Popen(["ssh", ...])` 直接以 `ssh` 为命令名调用，**依赖 `ssh.exe` 在 `PATH` 中**。本机路径为 `C:\Windows\System32\OpenSSH\ssh.exe`。

| 情形 | 表现 |
| --- | --- |
| 已安装（Win10 1809+ 默认可选功能） | 正常 |
| 未安装 / 未在 PATH | `Popen` 抛 `FileNotFoundError`（`[WinError 2] 系统找不到指定的文件`），被 `start_tunnel` 的 `except Exception` 捕获，弹"启动失败"并写日志，界面状态不变 |

安装方式（管理员 PowerShell）：

```powershell
# 查询是否已装
Get-WindowsCapability -Online -Name OpenSSH.Client*
# 安装客户端
Add-WindowsCapability -Online -Name OpenSSH.Client~~~~0.0.1.0
```

> 建议在手册与 README 都把这条列为"前置条件第一条"，因为它是最常见的"程序打不开隧道"根因。

**版本要求（v2.1 因密码认证而收紧）**：

| 功能 | 最低版本要求 | 原因 |
| --- | --- | --- |
| 密钥认证 | OpenSSH 7.x（Win10 1809 自带即满足） | 只用 `-i` / `-L` / `-o` 等常规参数 |
| **密码认证** | **OpenSSH 8.1.4+** | 依赖 `SSH_ASKPASS_REQUIRE=force` 强制走辅助程序；8.1.4 以前的版本忽略该变量，会尝试从控制台读口令而失败 |

本机实测 `OpenSSH_for_Windows_9.1.5p2`，两条路径均可用。用 `ssh -V` 确认版本；低于 8.1.4 时密码认证不可用（程序会在失败日志中提示检查版本），请改用密钥认证或升级 OpenSSH。

#### 2.10.2 PowerShell（v2.1 新增，仅密码认证需要）

askpass 辅助脚本用 `powershell.exe` 输出口令，目的是绕开 `cmd` 的代码页与转义问题（详见 5.3.3）：`echo` 方案会吃掉 `"` `&` `|` `<` `>` 等字符，并让中文口令变成乱码。

| 情形 | 表现 |
| --- | --- |
| PowerShell 可用（Windows 默认） | 正常，中文与特殊字符口令均正确 |
| 被组策略禁用 / 精简系统移除 | 脚本退回 `cmd` 延迟展开分支，纯 ASCII 口令仍可用，**中文口令可能乱码**，认证失败 |
| 无 `powershell` 但走密钥认证 | 完全不受影响（该脚本根本不会生成） |

#### 2.10.3 icacls（Windows 内置）

`_fix_key_permission` 调用 `icacls <key> /inheritance:r /grant:r <user>:(R)`。`icacls` 为 Windows 自带，正常系统必有；调用整体包在 `try/except` 中（含 `timeout=10`），失败只写日志不阻断流程（日志提示"修复密钥权限失败(可手动执行 icacls)"）。

#### 2.10.4 服务端 sshd（前置）

服务器需运行 `sshd`，并按所选用认证方式放行：

| 认证方式 | 服务端要求 |
| --- | --- |
| 密钥认证 | `server_key` 对应的公钥已写入目标用户的 `~/.ssh/authorized_keys`，`PubkeyAuthentication yes` |
| 密码认证 | `PasswordAuthentication yes`（部分发行版还需 `KbdInteractiveAuthentication yes`），改完 `systemctl reload sshd` |

本程序不负责生成密钥对、不上传公钥、不修改服务端配置。

### 2.12 依赖风险评估

| 风险点 | 影响 | 缓解 |
| --- | --- | --- |
| 外部 `ssh.exe` 版本差异 | 老版本不支持某些 `-o` 选项（如 `ExitOnForwardFailure`），参数被忽略或报错 | 要求 Windows 10 1809+ 自带 OpenSSH 8.x 以上 |

| PyInstaller 大版本变更 | spec 语法、onefile 行为差异 | 锁定 `pyinstaller==6.22.3` 或记录已验证版本 |

## 3. 配置与凭据

### 3.1 `config.json` 字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `server` | str | 服务器 IP / 域名 |
| `ssh_port` | str | SSH 端口（字符串，允许空） |
| `user` | str | 登录用户 |
| `key_path` | str | 私钥路径，**推荐裸文件名 `server_key`**（见 3.2） |
| `auth_method` | str | `key` / `password`，缺省按 `key` |
| `password_enc` | str | 密码的 DPAPI 密文，可缺省；**明文永不写入** |
| `panels` | list | `[{name, local_port, remote_port}, …]` |
| `current` | str | 当前面板名（下拉框只显示纯名称，不带端口后缀） |

约定：**空即空**——空值不会被回填成默认值；所有界面值来自配置，代码里禁止写死。

### 3.2 `key_path` 语义（V2.3 已收敛，禁止回改）

- 支持裸文件名与绝对路径两种写法；
- 相对路径按 **exe 同目录**解析（`_collect_config` L1026 → `_write_config` L1071 链路负责归一）；
- **V2.3 起 `dist\config.json` 中的 `key_path` 固定为裸文件名 `server_key`**，不再写 `E:\yscl\sgtunnel\dist\server_key` 这类绝对路径——绝对路径一旦换机即失效，且泄露本机目录结构；
- 这是配置语义的一部分，任何改动（含脚本批处理）都必须保持裸名，回归测试要校验该字段。

### 3.3 保存链路

| 入口 | 行号 | 触发 |
| --- | --- | --- |
| `save_config(silent=False)` | L1097 | 点「保存配置」 |
| `_auto_save()` | L1162 | 面板切换 / 退出前的静默保存 |
| `_on_close()` | L1850 | 关窗：脏则提示，退出前静默落盘 |
| `_write_config(data)` | L1068 | 真正的写盘（原子写 + 敏感键过滤） |
| `_collect_config()` | L1023 | 从界面控件聚合数据 |

### 3.4 DPAPI 实现（L158–L260）

| 符号 | 行号 | 作用 |
| --- | --- | --- |
| `_DATA_BLOB` | L158 | `ctypes` 结构体映射 `CRYPT_INTEGER_BLOB` |
| `_dpapi_load()` | L167 | 加载 `crypt32.dll` / `kernel32.dll` 并声明 `CryptProtectData` / `CryptUnprotectData` 原型 |
| `_blob_from(raw)` | L207 | bytes → DATA_BLOB |
| `dpapi_encrypt(plain)` | L214 | 加密（绑定当前 Windows 用户） |
| `dpapi_decrypt(token)` | L237 | 解密；失败抛异常由上层降级处理 |

密文只在**本机当前 Windows 用户**下可解。换机 / 换用户 / 密文被改动时，`load_config` → `_load_config_impl`（L873）会捕获异常、删除失效的 `password_enc`（`_drop_password_enc` L1004），并经 `_warn_decrypt_failed`（L990）给出**非阻塞**提示。

### 3.5 密码红线

- 明文只在内存与环境变量中流转，**不落盘、不进命令行参数、不进日志、不进任何临时文件**；
- 密码认证时通过 `SSH_ASKPASS` + 临时脚本递交（`_prepare_askpass` L1393 / `_cleanup_askpass` L1408），用完即删；
- 日志与错误提示中对密码一律脱敏。

### 3.6 原子写 `atomic_write_text()`（L114）

写配置统一走：**同目录临时文件 → `flush` + `os.fsync` → `os.replace`**。中途断电/被杀进程只会留下临时文件，原 `config.json` 永远是完整可解析的 JSON，不会出现「写一半变空文件、下次启动配置全丢」。

调用点：`_write_config` L1071 与 `_drop_password_enc` L1004。

**为什么它是唯一允许有缺省值的字段**：它表达的是"用哪种模式"，不是"要填什么值"。缺省 `key` 同时保证 v2.0 旧配置（无此字段）行为完全不变。

#### 3.7.5 `key_path`（密钥认证时必填，含相对路径解析规则）

| 项 | 内容 |
| --- | --- |
| 语义 | SSH 私钥文件路径 |
| 类型 | string，支持裸文件名 / 相对路径 / 绝对路径 |
| 空值行为 | 留空；密钥认证下启动前报"密钥文件为空" |
| 界面控件 | "密钥文件" 输入框（`var_key`） |
| 消费点 | `start_tunnel` 的 `os.path.exists` 校验、`_fix_key_permission` 的 `icacls` 目标、`build_cmd` 的 `-i` 参数 |

**读取侧规则**（`load_config`）：

```python
key_val = str(data.get("key_path") or "").strip()
if key_val:
    if not os.path.isabs(key_val) and os.sep not in key_val and "/" not in key_val:
        key_val = os.path.join(BASE_DIR, key_val)
    self.var_key.set(key_val)
```

只有**同时满足**三个条件才转换为 `BASE_DIR` 下的绝对路径：不是绝对路径、不含 `\`、不含 `/`。

**写入侧规则**（`_collect_config`，v2.1 新增）：

```python
if os.path.normcase(os.path.dirname(os.path.abspath(key_out))) == \
        os.path.normcase(os.path.abspath(BASE_DIR)):
    key_out = os.path.basename(key_out)
```

即：保存时若密钥位于程序同目录，**落盘只写裸文件名**，不写绝对路径。这样"exe + config + key"整包拷到任意目录/U 盘仍然可用，同时也修掉了 v2.0 遗留的"dist 里 config 写成旧绝对路径 `E:\yscl\sgtunnel\dist\server_key`"问题（下次保存即自动改写为 `server_key`）。

| 配置值 | 读取结果 | 保存后回写 | 说明 |
| --- | --- | --- | --- |
| `server_key` | `<程序目录>\server_key` | `server_key` | ✅ 推荐写法，目录整体搬动仍可用 |
| `keys\prod_key` | 原样保留（相对 CWD） | 原样 | ⚠️ 含分隔符不转换，行为依赖启动时工作目录，**不推荐** |
| `E:\yscl\...\server_key`（位于程序目录） | 原样保留 | `server_key` | 自动轻量化 |
| `D:\其它位置\key` | 原样保留 | 原样保留 | 绝对路径，机器/目录迁移后失效 |

#### 3.7.6 `panels`（必填数组）

| 项 | 内容 |
| --- | --- |
| 语义 | 面板列表，每项一组"名称 + 本地端口 + 远程端口" |
| 类型 | array\<object\>，长度 ≥ 1 |
| 空值行为 | 缺省时视为单面板、两端口均留空（不再兜底 40001） |
| 界面控件 | "面板选择"下拉框 + "本地端口" / "远程端口" 输入框 |

数组元素字段：

| 字段 | 类型 | 语义 | 约束 |
| --- | --- | --- | --- |
| `name` | string | 面板显示名，同时作为**唯一标识**（`current` 与查找逻辑都按名字匹配） | **必须唯一**；读取时重复名会自动加 `-2`、`-3` 后缀；缺失名自动填 `面板N` |
| `local_port` | string | 本地监听端口（`-L` 的左侧） | 需为 1–65535 的可转 `int` 字符串，且本机未被占用 |
| `remote_port` | string | 远端服务端口（`-L` 的右侧，落在服务器 `127.0.0.1` 上） | 需为 1–65535 的可转 `int` 字符串 |

**关键机制**：面板的增删仍只有一个入口 —— 编辑 `config.json` 后点"重新加载"。界面没有"新增 / 删除面板"按钮（见第 8 章 8.1.2.6）。新增一项只要在数组里加一个对象，`_refresh_panel_values` 会自动渲染进下拉框。

#### 3.7.7 `current`（选填）

| 项 | 内容 |
| --- | --- |
| 语义 | 上次选中的面板名，用于重启后恢复选择 |
| 类型 | string |
| 空值行为 | 取 `panels[0].name`（这是"选哪个"的选择行为，不是填值，不违反空即空原则） |
| 消费点 | `load_config` 初始化下拉框与端口；`_collect_config` 保存时写入当前选择 |

容错：若 `current` 的值在 `panels` 中找不到，`load_config` 回退到首个面板，不报错。

#### 3.7.8 `password_enc`（v2.2 新增，选填；不存在明文 `password` 字段）

**明文密码永不落盘**，这是第 10.5 节的红线；落盘的只有 `password_enc` —— 用 Windows DPAPI 加密后的 Base64 密文。

| 项 | 内容 |
| --- | --- |
| 语义 | 密码的加密快照，用于重启后自动回填密码框 |
| 类型 | string（Base64，典型长度 100~500 字符，取决于密码长度） |
| 生成时机 | `_write_config`：密码框非空 → `dpapi_encrypt(明文)` → 写入；密码框为空 → `data.pop("password_enc")`（字段整条删除） |
| 消费时机 | `load_config`：`dpapi_decrypt(值)` 成功则 `var_pwd.set(明文)`；失败则留空 + 弹提示 + 删字段 |
| 空值行为 | 字段缺失 → 密码框留空、不动文件；字段存在但为空串 / 纯空白 → 视同"没有保存密码"，密码框留空并顺手删除该空字段；`null` → 同"缺失" |
| 绑定范围 | **当前 Windows 用户账户**（DPAPI 用户级密钥）。换机器、换登录用户、重装系统后密文不可解，属预期行为 |
| 加密算法 | 由 Windows DPAPI 内部决定（当前为 AES-256，密钥由用户登录凭据派生并受 DPAPI 保护）；**密文本身不等于加密密码**，攻击者拿到密文也需能登录该用户才能解密 |

实现要点（`sgtunnel.py`）：

```python
CRYPTPROTECT_UI_FORBIDDEN = 0x01     # 禁止任何 UI 弹窗, 失败直接返回错误码

class _DATA_BLOB(ctypes.Structure):  # Windows DATA_BLOB
    _fields_ = [("cbData", ctypes.c_ulong),
                ("pbData", ctypes.POINTER(ctypes.c_char))]

def dpapi_encrypt(plain):   # 明文 -> Base64(密文); 失败返回 None
def dpapi_decrypt(token):   # Base64(密文) -> 明文; 任何失败返回 None
```

- **零第三方依赖**：`ctypes.WinDLL("crypt32")` / `WinDLL("kernel32")` 直调 `CryptProtectData` / `CryptUnprotectData` / `LocalFree`，函数 `argtypes` / `restype` 全部显式声明（避免 64 位指针被截断）。未使用 `pywin32`、`pycryptodome`、`cryptography`。
- **失败即 None，绝不抛异常**：`dpapi_encrypt` 失败时 `_write_config` 跳过写密文并记日志"警告: 密码加密失败(Windows DPAPI 不可用)…"；`dpapi_decrypt` 对非法 Base64、非本用户密文、被截断/篡改的密文一律返回 `None`。
- **内存释放**：解密/加密后的 `DATA_BLOB.pbData` 由 `LocalFree` 释放（`try/finally` 保证）。
- **明文的存在范围**：仅 `Tk` 变量 `var_pwd`、`TunnelApp._password`、`ssh` 子进程环境变量 `SG_TUNNEL_PW` 三处，均不涉及磁盘与命令行。

**判定口径**：`password_enc` 是"便捷性快照"，不是安全边界。它防的是"配置文件被随手拷走/上传网盘/贴进聊天窗口"这类泄露；它**不防**"攻击者已能登录该 Windows 用户"，此时 DPAPI 也会为其解密（见 8.1.2.8）。

### 3.8 生效时机（四个入口）

| 时机 | 方法 | 行为 |
| --- | --- | --- |
| 程序启动 | `load_config` | 先清空全部输入框 → 读文件 → 规范化 panels → 选面板 → 填 SSH 字段与端口 → 解密 `password_enc` 回填密码（失败则留空+提示+删字段） → 写一条日志 |
| 用户点"重新加载" | `load_config` | 同上，运行期热更新（**不会**中断已建立的隧道，改动只影响下次启动的隧道） |
| 用户点"保存配置" | `save_config` → `_collect_config` → `_write_config` | 收集界面值覆盖写文件；密码加密进 `password_enc`（空则删除该字段），成功后弹提示框（明示密文已保存 / 密文已删除） |
| 点"启动隧道"前 | `_auto_save` | **静默**保存（不弹框），防止改了没存导致下次启动丢失；此时机在校验通过后、`Popen` 之前 |

`_collect_config` 的回填逻辑：先把"界面当前端口"写回**当前选中面板**（按名字匹配），若当前名不在 `panels` 里则**追加一个新面板项**。因此把面板名改成新值再保存，会新建条目而非覆盖旧条目。

密码的落盘动作不在 `_collect_config` 里，而是集中在 `_write_config`（唯一写文件通道）：先 `pop` 掉任何 `password` / `passwd` / `pwd` 残留，再按密码框内容决定写入或删除 `password_enc`，最后落盘。这样任何调用 `_write_config` 的路径（手动保存、自动保存）都无法绕过加密。

### 3.9 空值 / 缺省矩阵（v2.2 实测行为）

| `config.json` 状态 | 界面表现 | 启动隧道时 |
| --- | --- | --- |
| 文件不存在 | 全部输入框空白，日志："未找到 config.json, 界面保持空白, 点保存配置后将生成" | 校验拦截：服务器 IP 为空、端口无效… |
| 文件存在但字段全空 | 全部输入框空白（不以任何默认值填充） | 同上 |
| 字段为 `null` | 该输入框空白（`str(x or "").strip()`） | 同上 |
| 字段为数字（如 `"ssh_port": 22`） | 正常显示 `22` | 正常通过 |
| `auth_method` 缺失 | 单选组停在"密钥认证" | 走密钥认证 |
| `auth_method": "password"` | 单选组停在"密码认证"，密钥框禁用、密码框可编辑 | 走密码认证，密码框为空则拦截 |
| 残留 `password` 字段 | 忽略，密码框保持空白；日志提示该字段已被忽略，保存时该字段被剔除 | — |
| `password_enc` 缺失 | 密码框空白，不报错也不改动文件 | 密码认证下被校验拦截（要求输入密码） |
| `password_enc` 为空串 / 纯空白 | 密码框空白；因字段存在但无值，视同"没有密码"，顺手 `_drop_password_enc()` 把该空字段清掉 | 密码认证下被校验拦截（要求输入密码） |
| `password_enc` 可正常解密 | 密码框自动填入明文（日志："已解密并回填密码(DPAPI 密文…"） | 直接可启动 |
| `password_enc` 解密失败 | 密码框留空 + 弹框"密码需要重新输入" + 字段被删除，其它字段照常加载 | 需重新输入密码 |

> 这张表是 v2.1/v2.2 的核心验收点：**没有任何一行会把空值变成默认值**；密码相关三行只影响密码框，不会波及其它字段。

### 3.10 旧格式兼容（v1.x → v2.1）

`load_config` 中的回退分支：

```python
panels = data.get("panels")
if not isinstance(panels, list) or len(panels) == 0:
    panels = [{
        "name": "面板1",
        "local_port": str(data.get("local_port") or "").strip(),
        "remote_port": str(data.get("remote_port") or "").strip(),
    }]
```

行为矩阵：

| 输入配置 | 结果 |
| --- | --- |
| 有合法非空 `panels` | 直接使用（名称去空、去重、端口转字符串） |
| 无 `panels`，但有顶层 `local_port` / `remote_port` | 升格为单元素数组，名称 `面板1`，端口沿用旧值（空则空） |
| 无 `panels`，也无端口字段 | 单元素数组 `面板1`，两端口空白 |
| `panels` 为 `null` / `{}` / `[]` / 字符串 | 同"无 panels"分支（`isinstance` + 长度双重判定） |
| v2.0 配置（含 `panels` + `current`，无 `auth_method`） | 原样加载，认证方式默认 `key`，行为与 v2.0 一致 |
| v1.x 配置（顶层端口、无 `auth_method`） | 单面板 + 密钥认证，`key_path` 仍是必填 |

> 兼容分支只在内存里补全，**不会自动写回文件**；只有点保存或触发 `_auto_save` 后文件才会升级（此时会多出 `auth_method` 与 `panels` 数组）。

### 3.11 读取侧的规范化清单

`load_config` 对 `panels` 做四道清洗，保证后续逻辑不需要防御性判断：

1. 非 `dict` 的元素直接丢弃；
2. `name` 为空 → 填 `面板N`（N 为原数组下标 +1）；
3. `name` 重复 → 追加 `-2` / `-3` 后缀，保证唯一；
4. 端口统一 `str(... or "").strip()`，保持字符串形态与空值。

清洗后若数组为空，兜底为单个 `面板1`（空端口）。

### 3.12 配置校验（v2.1 已前移）

v2.0 无任何校验，脏值一路流到 `int()` 才炸。v2.1 在 `start_tunnel` 最前面调用 `_validate`，**一次性收集所有错误**并弹一个聚合弹框：

| 校验项 | 触发条件 | 提示文案 |
| --- | --- | --- |
| 服务器 | `server` 为空 | 服务器 IP 为空 |
| 用户名 | `user` 为空 | 用户名为空 |
| SSH 端口 | `_parse_port` 返回 `None`（空/非数字/越界） | SSH 端口无效: 'xxx'(需为 1-65535 的整数) |
| 本地端口 | 同上 | 本地端口无效: 'xxx'(…) |
| 远程端口 | 同上 | 远程端口无效: 'xxx'(…) |
| 密钥（密钥认证） | 为空或文件不存在 | 密钥文件为空 / 找不到密钥文件: <路径> |
| 密码（密码认证） | 为空 | 密码为空(密码认证需要填写密码) |
| 本地端口占用 | `port_open` 探测为已占用 | 弹框"本地端口 N 已被其他程序占用…" |

校验失败时：不改变任何界面状态、不留密码残留（`self._password = ""`）、日志记一条"启动被拒绝: …"。

仍然是缺口的（不拦截，流向下游）：

- `panels[].name` 含 ` (` 会引发旧式标签解析歧义（见 8.1.2.6）；
- 同一 `local_port` 被多个面板共用 → 启动第二个时被 `ExitOnForwardFailure=yes` 打断（端口占用预检能提前发现）；
- `remote_port` 在服务器上无服务监听 → ssh 不报错，只有浏览器打开时失败（隧道通 ≠ 远端服务在跑）。

新增一个"Grafana 面板（本地 13000 → 远端 3000）"：

```json
"panels": [

    { "name": "雷池面板",  "local_port": "16002",  "remote_port": "16002"  },
```

### 3.14 配置设计原则

界面**不含任何硬编码默认值**：所有 `Entry` / `Combobox` 初值一律来自 `config.json`。v2.1 起这条原则被收紧为一条更强的规则：

> **空即空**。`config.json` 中字段为空字符串、`null` 或字段缺失时，对应输入框**保持留空**，不回填任何"出厂默认值"或模板值。

v2.1 相对 v2.0 的关键变化：

1. **删除了 `_ensure_default_config` 自举模板**。v2.0 首次运行会写入一份含 `22022` / `root` / `server_key` / `40001` / `16002` 的模板配置，v2.1 不再生成 —— 无配置文件时界面全空，仅在日志区提示"点保存配置后将生成"。
2. **删除了 `load_config` 里 `panels` 端口兜底 `40001`**。旧格式兼容分支现在保留空端口，不再注入默认端口。
3. **新增 `auth_method`（认证方式）字段**，取值 `key` / `password`。它是"模式选择"而非"待填值"，因此是全表唯一一个有缺省取值的字段（缺失按 `key`）。

版本号不再硬编码：`APP_NAME = "爽哥面板隧道助手"` / `APP_VER = "2.4"` 为模块级常量，窗口标题与界面标题统一引用 `f"{APP_NAME} v{APP_VER}"`。

v2.2 相对 v2.1 的配置层变化只有一条：**新增 `password_enc`（密码密文）字段**，用于"重启自动回填密码"；该字段是可选的派生字段，不参与任何必填校验，缺失等价于"没有保存密码"。

### 3.15 config.json 完整结构

```json
{
    "server": "<服务器公网 IP 或域名>",
    "ssh_port": "22022",
    "user": "root",
    "auth_method": "password",
    "key_path": "",
    "password_enc": "<Base64 形式的 DPAPI 密文>",
    "panels": [
        { "name": "1Panel 面板", "local_port": "40001", "remote_port": "40001" },
        { "name": "雷池面板",  "local_port": "16002",  "remote_port": "16002"  }
    ],
    "current": "1Panel 面板"
}
```

> 以上为**结构与字段示意**；`server` 实际取值请查阅本机 `config.json`，本手册不记录具体地址。端口与主机字段在 JSON 中均为**字符串**，建议不要写成数字 —— 读取侧用 `str(value or "").strip()`，数字会被照常转换，但 `null` 会被 `or ""` 吃掉（等价空）而不是变成 `"None"`。
>
> 按密钥认证使用时 `auth_method` 为 `"key"`、`key_path` 有值、通常不出现 `password_enc`；按密码认证使用时 `key_path` 通常为空、有值的是 `password_enc`。

**配置里永远不会出现明文密码字段**。密码只以 `password_enc`（DPAPI 密文 + Base64）形式落盘。若历史文件中残留 `password` / `passwd` / `pwd`，`load_config` 会**忽略并写一条日志提示**，绝不加载到界面；保存时 `_write_config` 还会主动把这些字段**剔除**，确保不会被回写。

## 4. 架构与线程模型

### 4.1 单主线程 + 消息泵

Tk 控件只允许在主线程操作。所有后台线程的 UI 动作统一走消息队列：

| 符号 | 行号 | 说明 |
| --- | --- | --- |
| `_post(kind, *args)` | L806 | 任意线程投递消息（线程安全） |
| `_drain_ui()` | L810 | 主线程消息泵：按批取消息分发，随后自适应安排下一次 |
| `_dispatch(kind, args)` | L835 | 消息分发：`log` / `state` / `started` / `start_error` / `stopped` / `probe` |
| `DRAIN_START_MS` | L76 | 初始间隔 100 ms |
| `DRAIN_FAST_MS` | L77 | 有新消息后 30 ms（日志滚动顺滑） |
| `DRAIN_IDLE_MS` | L78 | 连续空闲退避上限 250 ms（不再固定 100 ms 空转） |
| `DRAIN_BATCH` | L79 | 单轮最多 200 条（ssh 刷屏也不卡界面） |

铁律：**后台线程绝不直接碰控件**；`log()`（L1177）、`_set_state()`（L1308）内部会自动判断当前线程，非主线程自动转 `_post`。

### 4.2 后台线程清单

| 线程 | 入口 | 职责 |
| --- | --- | --- |
| 启动线程 | `_start_worker` L1568 | 端口预检 → 私钥权限修复 → 拼命令 → `Popen` 拉起 ssh |
| 停止线程 | `_stop_worker` L1755 | `terminate` → 等待 → 兜底 `kill` → 回收子进程 |
| 监控线程 | `_monitor` L1675 | 运行期监听进程退出，`_proc_exit`（L1719）处理异常退出 |
| 端口探测 | `_probe_worker` L1823 | 后台 `port_open` 探测本地端口，结果 `_post("probe")` 回主线程（含 `try/finally` 释放 `_probe_busy`） |

### 4.3 状态机（四态 + 停止）

状态常量：L83–L87（`STATE_IDLE` / `STATE_STARTING` / `STATE_RUNNING` / `STATE_ERROR` / `STATE_STOPPED`）。
样式表 `STATE_STYLE`（L280–L286）：**文案与颜色一一绑定**，杜绝「文字变了颜色没变」。

| 状态 | 文案 | 颜色 |
| --- | --- | --- |
| `idle` | ● 隧道未运行 | 灰 `#a6adc8` |
| `starting` | ● 隧道启动中... | 黄 `#f9e2af` |
| `running` | ● 隧道已连接 ✅ | 绿 `#a6e3a1` |
| `error` | ● 隧道出错, 详见日志 | 红 `#f38ba8` |
| `stopped` | ● 隧道已停止 | 灰 `#a6adc8` |

设置状态只有一条路径：`_set_state`（L1311，判线程）→ `_set_state_now`（L1318，改文案+颜色，并调用 `_refresh_buttons`）。**禁止在别处直接 `status.config(...)`**。

### 4.4 按钮启用矩阵（`_refresh_buttons` L1328）

| 按钮 | 可用条件 |
| --- | --- |
| 启动隧道 | 非 `starting/running` 且非忙碌 |
| 停止隧道 | `starting/running` 且非忙碌 |
| 打开面板 | `state == running` |
| 保存配置 | 非忙碌；**有未保存改动时底色变黄**（`BTN_DIRTY` L277，应用点 L1339） |
| 重新加载 | 非忙碌 |

### 4.5 隧道协议与 `ssh` 命令构造

`build_cmd` 先拼公共参数，再按 `auth_method` 追加认证相关项：

```python
# 优先用 start_tunnel 校验过的快照(self._lport 等); 未启动时回退到界面值,
# 保证任何调用入口都不会 AttributeError, 也不会把未校验的空值拼进命令
lport   = getattr(self, "_lport", "")  or self.var_lport.get().strip()
rport   = getattr(self, "_rport", "")  or self.var_rport.get().strip()
sshport = getattr(self, "_sshport","") or self.var_port.get().strip()
user    = getattr(self, "_user", "")   or self.var_user.get().strip()
server  = getattr(self, "_server", "") or self.var_ip.get().strip()
key     = getattr(self, "_key", "")    or self.var_key.get().strip()
auth    = getattr(self, "_auth", "")
if auth not in (AUTH_KEY, AUTH_PASSWORD):
    auth = self.var_auth.get()
if auth not in (AUTH_KEY, AUTH_PASSWORD):
    auth = AUTH_KEY                      # 兜底默认密钥认证

cmd = ["ssh", "-N",
       "-L", f"{lport}:{REMOTE_HOST}:{rport}",
       "-p", sshport,
       "-o", "StrictHostKeyChecking=no",
       "-o", "ServerAliveInterval=30",
       "-o", "ExitOnForwardFailure=yes"]
if auth == AUTH_PASSWORD:
    cmd += ["-o", "BatchMode=no",
            "-o", "PubkeyAuthentication=no",
            "-o", "PreferredAuthentications=password,keyboard-interactive",
            "-o", "NumberOfPasswordPrompts=1"]
else:
    cmd += ["-i", key]
cmd.append(f"{user}@{server}")          # 密码永远不出现在这里
```

> **v2.2 顺带修正（`build_cmd` 自包含）**：v2.1 的 `build_cmd` 直接读 `self._lport` / `self._sshport` 等属性，而这些属性只在 `start_tunnel` 里赋值 —— 任何在"未启动"状态下调用它（预检、单测、脚本化自检）都会 `AttributeError`。v2.2 改为"快照优先 + 界面值回退 + 认证方式兜底"，正常启动路径行为不变。

公共参数语义与选择理由：

| 参数 | 含义 | 为什么这么选 |
| --- | --- | --- |
| `-N` | 不执行远程命令，仅做转发 | 只建通道，不开 shell，进程更轻、退出更可控 |
| `-L L:127.0.0.1:R` | 本地转发：监听 `127.0.0.1:L`，流量经 SSH 通道送到服务端再由服务端连 `127.0.0.1:R` | 远端固定回环（`REMOTE_HOST` 常量），面板端口无需对公网监听 |
| `-p` | 远程 sshd 端口 | 支持非 22 端口 |
| `StrictHostKeyChecking=no` | 跳过主机公钥校验，新主机自动接受 | **取舍**：换服务器无需清 `known_hosts`，但失去中间人防护（见 8.1.2.1） |
| `ServerAliveInterval=30` | 每 30 秒发保活探测 | 防止 NAT/防火墙空闲断链 |
| `ExitOnForwardFailure=yes` | 转发建立失败即整体退出 | 避免"进程活着但端口没起来"的假成功态 |

认证分支参数（仅密码认证）：

| 参数 | 作用 | 不这么写会怎样 |
| --- | --- | --- |
| `BatchMode=no` | 允许交互式认证 | `BatchMode=yes` 会直接拒绝任何提示，密码路径失效 |
| `PubkeyAuthentication=no` | 跳过公钥尝试 | 否则本机默认密钥会被先试一遍，可能连到不该连的账号，也拖慢失败反馈 |
| `PreferredAuthentications=password,keyboard-interactive` | 只走密码类认证 | 部分服务器把密码包装成 `keyboard-interactive`，两者都要留 |
| `NumberOfPasswordPrompts=1` | 只提示一次 | 防止密码错误时 ssh 反复重试导致 15 秒等待期内多次触发 askpass |

> **转发的是 TCP 流，不是 HTTP 代理**。面板是 HTTPS，TLS 由浏览器与远端面板端到端协商，SSH 层只做加密运载，不做 TLS 卸载 —— 因此不会因隧道产生证书链错误（但证书域名与 `127.0.0.1` 不符时浏览器仍可能告警，属面板侧配置问题）。

### 4.6 鉴权链路（密钥 / 密码 / DPAPI 回填）

#### 4.6.1 两条分支的统一前置流程

```
用户点"启动隧道"
  → ① 主线程快照 UI 值（含密码字符串）
  → ② _validate()：一次性收集全部配置错误 → 有错弹聚合框并 return（清空 _password）
  → ③ 本地端口占用预检（port_open 探测，占用则弹框并 return）
  → ④ 按认证方式分支（见下）
  → ⑤ build_cmd() 拼命令
  → ⑥ _auto_save() 静默落盘配置（密码以 DPAPI 密文写入 password_enc）
  → ⑦ Popen 拉起 ssh（stderr 合流 stdout，UTF-8，CREATE_NO_WINDOW）
  → ⑧ 切按钮态、置状态"启动中"，起 daemon 监控线程
```

#### 4.6.2 密钥认证分支

```python
self._fix_key_permission(self._key)   # icacls 收紧 ACL
cmd += ["-i", self._key]
```

`_fix_key_permission` 细节：

```python
user = os.getenv("USERNAME") or "Administrator"
subprocess.run(["icacls", key, "/inheritance:r", "/grant:r", f"{user}:(R)"],
               capture_output=True, text=True, timeout=10)
```

- `/inheritance:r` 移除继承 ACE，`/grant:r` 只授予当前用户读权限 —— OpenSSH 要求私钥"仅所有者可访问"，继承权限过宽会报 `Bad permissions` 直接拒绝加载。
- 包在 `try/except` + `timeout=10`，失败仅写日志，不阻断启动（ssh 之后会自己报错，日志里能看到原因）。

#### 4.6.3 密码认证分支（v2.1 新增，核心机制）

**目标约束**：密码不得写入 `config.json`，不得出现在 `ssh` 的命令行参数里（命令行可被任务管理器/审计工具读到）。

实现路径是 OpenSSH 官方的 `SSH_ASKPASS` 机制：

```
[界面输入密码]
   → self._password（内存）
   → 子进程环境变量 SG_TUNNEL_PW（仅 ssh 进程及其子进程可见）
   → ssh 需要口令时执行 ASKPASS 脚本
   → 脚本把 $env:SG_TUNNEL_PW 写到 stdout
   → ssh 从 stdout 读到口令
```

关键代码：

```python
env = dict(os.environ)
env.update({
    "SSH_ASKPASS": askpass,          # 辅助脚本路径
    "SSH_ASKPASS_REQUIRE": "force",  # 强制使用 askpass, 不弹出控制台输入
    "DISPLAY": os.environ.get("DISPLAY", "localhost:0"),  # 部分 OpenSSH 版本要求该项存在
    "SG_TUNNEL_PW": self._password,  # 唯一的密码载体
})
kwargs["stdin"] = subprocess.DEVNULL   # 明确无 tty, 迫使 ssh 走 askpass
kwargs["env"] = env
```

辅助脚本 `ASKPASS_SCRIPT` 的形态（**脚本内容固定，不含任何密码**）：

```bat
@echo off
setlocal EnableDelayedExpansion
powershell -NoProfile -NonInteractive -Command "[Console]::OutputEncoding=[System.Text.Encoding]::UTF8; [Console]::Out.Write($env:SG_TUNNEL_PW)" 2>nul
if errorlevel 1 echo(!SG_TUNNEL_PW!
endlocal
```

两个容易踩的实现细节，改动时别动：

1. **必须用 `powershell` + `[Console]::Out.Write` 输出**，不能用 `echo`。原因：`echo` 会把 `"` / `^` / `&` / `|` / `<` / `>` 当控制字符吃掉，且 cmd 的代码页会让中文密码变成乱码。实测：`echo` 方案下 `p@ss&word|<>^` 与中文密码都会输出错误字节；`[Console]::Out.Write` + UTF8 编码后全部原样输出。
2. **`echo(!SG_TUNNEL_PW!` 的 `(` 是有意的**。当变量为空时 `echo(` 输出空行而不是打印 `ECHO is on`；同时延迟展开 `!VAR!` 能保留 `!` 字面量。

`SSH_ASKPASS_REQUIRE=force` 需要 OpenSSH 8.4+。本机实测版本 `OpenSSH_for_Windows_9.5p2`（见 3.3.1），满足要求。若在老版本上跑，`force` 值会被忽略，届时密码路径会失败 —— 日志里已内置提示："若确认密码正确仍认证失败, 请检查系统 OpenSSH 是否支持 SSH_ASKPASS(ssh -V)"。

**临时文件生命周期**（`_prepare_askpass` / `_cleanup_askpass`）：

| 时机 | 动作 |
| --- | --- |
| 密码认证启动前 | `tempfile.mkdtemp(prefix="sgtunnel_askpass_")` 建目录，写 `askpass.cmd`（UTF-8 + CRLF） |
| 写入内容 | 只有脚本模板，无密码 |
| 停止隧道 / 进程退出 / 启动失败 / 关窗 | `shutil.rmtree(dir, ignore_errors=True)` 删除目录 |
| 程序异常崩溃 | 目录残留在 `%TEMP%`，可手工清理；因不含密码，无泄露风险 |

> **凭据边界（可写进审计结论）**：程序全程不读私钥内容、不解析私钥格式、不打印密码。命令行里只有 `-i <路径>`（密钥认证）或无任何凭据（密码认证）。密码的落点是两处：进程环境变量（运行时）+ `password_enc` 密文（配置持久化，v2.2 起）。Windows 下读取其它进程的环境块需要 `PROCESS_VM_READ` 权限，普通同级进程拿不到 —— 比"命令行明文"和"配置文件明文"都安全，但仍不是"凭据管理器级"的强保护（见 8.1.2.8）。

#### 4.6.4 密码加密存储与重启回填（v2.2 新增，核心机制）

**目标约束**：密码要能被重启后的程序自动取用，因此必须落盘；但落盘内容不得是可读明文，且不得引入第三方依赖。

**方案**：Windows DPAPI（Data Protection API）用户级加密 + Base64 文本封装。

```
[界面密码框 var_pwd]
   ├─ 保存配置 → _write_config
   │     └─ dpapi_encrypt(明文) → CryptProtectData(UI_FORBIDDEN)
   │           → Base64 → config.json["password_enc"]
   └─ 启动加载 → load_config
         └─ dpapi_decrypt(password_enc) → base64 解码 → CryptUnprotectData(UI_FORBIDDEN)
               → 明文 → var_pwd.set(明文)
```

**ctypes 调用要点**（逐条都是"写错就静默失败"的坑）：

| 要点 | 写法 | 不这么写的后果 |
| --- | --- | --- |
| 结构体 | `_DATA_BLOB(cbData: c_ulong, pbData: POINTER(c_char))` | 结构错位，DPAPI 读到垃圾长度 |
| 函数签名 | `argtypes` / `restype` 全部显式声明 | 64 位下指针被默认 `c_int` 截断 → 访问违规或解密失败 |
| 出口参数 | `CryptUnprotectData` 第二参传 `POINTER(c_wchar_p)`，调用时给 `None` | 传 `c_void_p` 也能跑，但类型不匹配易在严格模式下崩 |
| 标志位 | `CRYPTPROTECT_UI_FORBIDDEN = 0x01` | 缺省会允许 DPAPI 弹 UI（在无交互进程里直接挂起） |
| 内存 | `LocalFree(cast(pbData, c_void_p))` 放 `finally` | 每次加解密泄漏一块 DPAPI 分配的内存 |
| 失败判定 | 返回值为 0 即失败，一律 `return None` | 抛异常会打断保存/加载主流程 |

**关键分支行为**：

| 场景 | 行为 |
| --- | --- |
| 密码框有值 → 保存 | 写 `password_enc`；日志"密码已用 Windows DPAPI 加密后保存"；弹框说明密文绑定当前用户 |
| 密码框为空 → 保存 | `password_enc` 整条删除；日志"密码框为空, 已清除配置中的密码密文(password_enc)" |
| 加密函数返回 `None` | 不写密文、删旧密文、日志警告"本次未保存密码, 重启后需要重新输入"（不阻断保存其它字段） |
| 加载时无 `password_enc` | 密码框留空，静默 |
| 加载时 `password_enc` 为空串 / 纯空白 | 字段存在但无值 → 视同"没有密码"：密码框留空，并调用 `_drop_password_enc()` 把这个空字段清掉（保持文件整洁，不弹提示） |
| 加载时解密成功 | `var_pwd.set(明文)`，日志"已解密并回填密码(DPAPI 密文, 仅当前 Windows 用户可解)" |
| 加载时解密失败 | ① 密码框留空 ② `_drop_password_enc()` 删除失效字段（保留其它字段） ③ 日志两条说明 ④ `root.after(200)` 弹警告框"密码需要重新输入"，不阻断启动 |

**为什么失效提示用 `root.after` 而不是直接 `messagebox`**：`load_config` 在 `__init__` 中调用，此时窗口尚未 `mainloop`，直接弹模态框会卡在构造阶段；且"重新加载"按钮也会走 `load_config`，同步弹框会阻塞按钮回调。推迟到事件循环里执行，两种入口都安全（与 8.1.3 的队列化原则一致）。

**`_drop_password_enc` 为什么独立成方法**：它只做"读文件 → 删一个键 → 写回"，不经过 `_write_config`（后者会重新加密密码框内容，而此时密码框正是空的，会把整条记录连带其它状态重算一遍）。该方法失败也只记日志返回 `False`，提示文案会改成"失效密文删除失败，可手工删除 password_enc 字段"。

### 4.7 健康检查与状态机

| 状态 | 文案 | 颜色 | 触发 |
| --- | --- | --- | --- |
| 初始 | `● 隧道未运行` | `#f9e2af` | `__init__` |
| 启动中 | `● 隧道启动中...` | `#f9e2af` | `start_tunnel` 后、`_tick` 探测失败且进程存活 |
| 已连接 | `● 隧道已连接 ✅` | `#a6e3a1` | `_monitor` 阶段1 就绪 / `_tick` 探测成功 |
| 已断开 | `● 隧道已断开` | `#f38ba8` | `_proc_exit`（进程退出） |
| 已停止 | `● 隧道已停止` | `#f38ba8` | `stop_tunnel`（用户主动停止） |

`port_open` 实现（v2.1 已内置容错）：

```python
@staticmethod
def _parse_port(text):
    try:
        port = int(str(text).strip())
    except (TypeError, ValueError):
        return None
    return port if 1 <= port <= 65535 else None

def port_open(self, host="127.0.0.1", port=None, timeout=1.0):
    port = self._parse_port(port)
    if port is None:
        return False
    try:
        s = socket.create_connection((host, port), timeout=timeout)
        s.close()
        return True
    except OSError:
        return False
```

**调用方不再自行 `int()`**：`_monitor`、`_tick`、`open_panel` 全部改用 `_parse_port` 并显式处理 `None`。这消除了 v2.0"端口填非数字 → 监控线程静默死亡"的整条故障链（详见 8.1.1 的修复记录）。

### 4.8 错误处理矩阵

| 失败场景 | 捕获位置 | 用户可见反馈 | 程序状态 |
| --- | --- | --- | --- |
| `config.json` 读失败（语法错、编码错） | `load_config` 的 `except Exception` | 日志"读取配置失败: ..."，界面保持空白 | 继续可用 |
| 顶层不是 JSON 对象 | `load_config` 的 `isinstance` 判定 | 日志"顶层不是对象" | 继续可用 |
| 配置写失败（目录只读） | `_write_config` | `messagebox.showerror("保存失败")` + 日志 | 返回 `False`，调用方中止 |
| 配置项非法（空值/非数字/越界） | `_validate` | **聚合弹框**列出全部问题 + 日志"启动被拒绝: ..." | 不改变任何状态 |
| 本地端口被占用 | `start_tunnel` 的预检 | 弹框"本地端口 N 已被其他程序占用" | 不启动 |
| 私钥不存在 | `_validate` | 弹框"找不到密钥文件: <路径>" | 不启动 |
| 密码为空（密码认证） | `_validate` | 弹框"密码为空(密码认证需要填写密码)" | 不启动 |
| askpass 脚本创建失败 | `_prepare_askpass` | 弹框"密码认证不可用…请改用密钥认证" | 不启动 |
| `icacls` 失败/超时 | `_fix_key_permission` | 日志"修复密钥权限失败(可手动执行 icacls)" | 继续启动（交给 ssh 报错） |
| `ssh` 未安装 / `Popen` 失败 | `start_tunnel` 的 `except Exception` | 弹框"启动失败" + 日志；同时回收 askpass | `running` 未置真 |
| ssh 认证失败 / 主机不可达 | 只能从 ssh 输出观察 | 日志出现 `ssh: Permission denied (...)` 原文；`_tick` 2 秒内翻"已断开" | 自动回可重试态 |
| 密码错误 | 同上 | ssh 原文 + 一条 `SSH_ASKPASS` 版本提示 | 同上 |
| `stop` 时 ssh 不退出 | `stop_tunnel` 捕获 `TimeoutExpired` | 日志"ssh 未在 5 秒内退出, 强制结束" → `kill()` → `wait(3)`；仍超时再提示任务管理器 | 正常落到"已停止" |
| 关窗时 ssh 不退出 | `_on_close` 捕获 `TimeoutExpired` | 无弹框（正在销毁） | `kill()` 后 `destroy()` |

日志格式统一为 `[HH:MM:SS] 消息`，ssh 输出统一前缀 `ssh: `，便于区分"程序自己的话"与"ssh 说的话"。日志仍只存在于界面 `Text` 控件，**不落盘**（见 8.1.2.4）。

### 4.9 UI 层要点

- 窗口 `640x820`，`minsize(640, 820)` 锁死，`resizable(False, False)`，暗色主题（`BG #1e1e2e`、`FG #cdd6f4`）；日志框 `height=5`。历史尺寸演进：v2.0 `620x740` → v2.1 因新增"认证方式"一行加高到 740 → **V2.3 因按钮区右侧加入赞助卡片（含 125px 二维码）加高到 820**，实测布局需求 813px < 820px，二维码与日志区均无裁剪、无挤压（详见 5.8）。

### 4.10 代码总体结构

单文件 1,110 行（v2.2 由 765 行增至 981 行，v2.3 增至 1,110 行），结构仍极简，v2.1 新增了认证分支与跨线程消息通道，v2.2 新增 DPAPI 加解密层，v2.3 新增资源路径解析与赞助卡片：

### 4.11 线程与并发模型（v2.1 起改为队列驱动）

```
主线程（Tk mainloop）
 ├─ UI 回调：按钮点击、下拉选择、单选切换
 ├─ after(100)  _drain_ui    ← 消费 _ui_q，所有控件更新都发生在这里
 ├─ after(2000) _tick        ← 端口轮询 / 退出兜底
 └─ 起 1 个 daemon 线程 → _monitor

子进程：ssh.exe（独立进程，非线程）
子进程：askpass.cmd → powershell（仅密码认证时，瞬时存活的孙子进程）
```

| 组件 | 周期 | 职责 | 线程 |
| --- | --- | --- | --- |
| `_drain_ui` | 每 100 ms | 从 `_ui_q` 取 `("log", msg)` / `("status", text, color)` / `("exited",)` 三类消息并更新控件 | 主线程（`root.after`） |
| `_monitor` | 一次性启动，循环至退出 | 阶段1：最多 30×0.5s 等本地端口就绪；阶段2：`for line in iter(proc.stdout.readline, "")` 逐行转发 ssh 输出，流关闭即结束 | 后台 daemon |
| `_tick` | 每 2000 ms | 重新探测本地端口；端口通→绿色"已连接"，不通且进程已退出→`_proc_exit` | 主线程（`root.after`） |

跨线程的唯一通道：

```python
def _post(self, kind, *args):          # 后台线程侧：只入队
    self._ui_q.put((kind, args))

def log(self, msg):                     # 双模：主线程直写，后台线程入队
    if threading.current_thread() is threading.main_thread():
        self._log_now(msg)
    else:
        self._post("log", msg)
```

这套"双模入口"的用意：主线程调用 `log()` 立即上屏（保证用户点"保存配置"时日志即时出现），后台线程调用则自动改走队列，调用方不需要关心自己处在哪个线程。`set_status` 同理。

`_drain_ui` 的防御：`queue.Empty` 之外任何异常都被捕获并写一条"界面更新异常"，避免单条坏消息终止整个消息泵（泵停在异常处会导致界面永久失去日志更新）。

剩余特征：

1. **`readline()` 仍是阻塞调用**。阶段2 用 `iter(readline, "")` 而非 `while True: readline()`，好处是 stdout 关闭（进程退出）时迭代自然结束，不需要靠 `poll()` 判断；但 ssh 静默时该调用依然阻塞。退出检测的实际主力仍是`_tick` 的 2 秒轮询（见 8.1.4）。
2. **`running` 与进程实际状态解耦**。用户点停止后 `running=False`，`_monitor` 的循环最多再跑一圈就退出，不会与新进程混线。

### 5.2 赞助支持卡片（V2.3）

参考实现：`E:\yscl\vaultwarden-manager\DEV.md` 第 4.9 节「赞助支持卡片」与第 4.10 节「图标资源与加载」。本项目按 tkinter 单窗口、`pack` 布局的特点做了适配，**没有沿用参考项目的"绝对路径写死"做法**，改为资源随包 + 三档兜底。

#### 5.2.1 位置与布局

- **落点**：按钮区容器 `mid`（`fill="x", padx=20, pady=(6,2)`）内的**右侧空白区**。按钮组 `btns` 用 `pack(side="left")`，卡片 `card` 用 `pack(side="right", anchor="n")`，二者横向并列、互不覆盖。
- **为什么不在底部**：窗口是 `resizable(False, False)` 的窄窗口（640 宽），底部已被状态栏与日志区占满；按钮区右侧原本只有一行"打开面板"与两行小按钮，右侧留白明显，放卡片既填补空白又不动任何既有控件的位置。
- **零挤压保障**：卡片是 `mid` 的子控件，`mid` 本身高度由按钮组决定，卡片高度（约 190px）小于按钮组高度（4 行按钮 ≈ 210px），所以 `mid` 高度不变、日志区 `fill="both", expand=True` 分到的空间不变。实测日志区仍保持 `height=5` 的原始行高。
- **构建顺序（关键）**：`_build_sponsor_card(mid)` 必须在 `self.log_box` 创建**之后**调用。图片加载失败要写日志，若 `log_box` 尚不存在，`self.log(...)` 会抛 `AttributeError` 并让整个窗口构建失败。当前顺序：标题 → 配置区 → 状态区 → 按钮区 → **日志区** → **赞助卡片** → `_on_auth_change()` → 启动消息泵。

#### 5.2.3 资源路径三档兜底（`asset_path`）

```python
cands = []
if sys._MEIPASS:  cands.append(<_MEIPASS>/assets/<name>)   # ① 打包态（spec datas 解包目录）
cands.append(<BASE_DIR>/assets/<name>)                     # ② exe 同级 / 源码根目录
if 源码目录 != BASE_DIR: cands.append(<源码目录>/assets/<name>)  # ③ 源码态
for p in cands: if os.path.isfile(p): return p
return None
```

- `BASE_DIR` 沿用既有定义：冻结态取 `dirname(sys.executable)`，源码态取 `dirname(__file__)`。
- ①②③ 覆盖三种分发形态：单文件 exe（①）、绿色分发且把 `assets` 放在 exe 旁边的目录（②）、源码直跑（③）。
- 每个候选都用 `try/except` 包住（非法路径字符等异常不中断），**全不命中返回 `None`**，由调用方决定降级行为——函数自身不写日志、不弹窗。

#### 5.2.4 二维码双通道加载

| 通道 | 实现 | 结果 | 触发条件 |
| --- | --- | --- | --- |
| 一（首选） | `from PIL import Image, ImageTk` → `Image.open` → `img.load()` → `convert("RGBA")` → `thumbnail((125,125), Image.LANCZOS)` → `ImageTk.PhotoImage` | 250×250 原图 → **125×125**（等比，LANCZOS 保证二维码边缘锐利可扫） | Pillow 与 ImageTk 均可导入 |
| 二（零依赖兜底） | `tk.PhotoImage(file=path)` 原生 PNG 解码 → `factor = ceil(longest/125)` → `subsample(2,2)` | 250×250 → **125×125** | Pillow 缺失、导入异常、解码异常、上屏异常 |

- **Pillow 是可选增强**：`_qr_via_pil` 内部 `try: from PIL import ... except Exception: return None`，整段导入失败直接降级；源码**没有顶层 `import PIL`**，因此 PyInstaller 的 `excludes` 排除 Pillow 后程序依然完整可用（这是 v2.3 打包的红线，见 7.9）。
- **防 GC 空白**：`ImageTk.PhotoImage` / `tk.PhotoImage` 都只是 Python 对象，若不保留引用，函数返回后即被垃圾回收，界面上只剩一片空白。因此加载成功后立刻 `self._sponsor_qr_photo = photo`（`__init__` 中预置 `None`），Label 只做展示。
- **缩放策略**：Pillow 通道用 `thumbnail` 严格等比且不放大；tk 通道只能整数倍降采样（`subsample`），故 `SPONSOR_QR_MAX = 125` 特意取 250 的一半，使降采样恰好命中 125×125，避免出现 83×83 之类的次优尺寸。

#### 5.2.5 容错（不崩、不弹窗、不塌陷）

| 故障 | 表现 | 处置 |
| --- | --- | --- |
| 图片不存在（`asset_path` 返回 `None`） | 卡片只剩标题 + 文案 | `_sponsor_warn("赞助二维码图片不存在, 已跳过显示(卡片仅保留文字): assets\\sponsor_qr.png")` 后 `return` |
| 图片内容损坏（非 PNG / 截断） | 同上 | 两条通道各自返回 `None` → `_sponsor_warn("赞助二维码加载失败(两条通道均不可用), 已跳过显示: <path>")` |
| Pillow 存在但上屏异常 | 自动走 tk 通道 | 通道一静默返回 `None`，不记日志（避免正常降级刷屏） |
| 卡片构建整体异常 | 主界面照常构建 | `_build_sponsor_card` 内 `try/except Exception as e` 兜底 → `_sponsor_warn(f"赞助二维码加载失败, 已跳过显示: {e}")` |
| `log_box` 尚未创建 | 丢弃这条日志 | `_sponsor_warn` 检查 `getattr(self, "log_box", None)`，为 `None` 时静默返回 |

- **纯展示**：卡片不绑定 `command`/`bind`，完全静态；**不参与 `_busy` 状态矩阵**，隧道启动/停止/连接中都保持原样，不会被 `state=disabled` 波及。
- **不塌陷**：卡片内各控件都是"缺失即少一行"，Frame 用 `pack` 自然收缩，宽度由文案 `wraplength` 撑定（约 184px），不会因缺图而变成一条细线。

| 主体边界 | 以亮度阈值扫描得到内容框 **`(82, 74, 1476, 1516)`**，即 1394×1442（主体四周有浅色留白与柔光，不能直接把 1536 画布当图标用） |
| 圆角半径 | 沿边界实测约 **225px**（占短边 16%） |
| 四角状态 | 圆角矩形以外的四角为**亮白/浅色不透明底** → 必须挖成透明 alpha，否则在深色任务栏上会出现白角 |
| 结论 | ① 裁到内容边界；② 按实测半径套圆角 alpha 蒙版（四角透明）；③ 保比例缩放，不拉伸。**除此之外不做任何像素级加工** |

#### 5.3.2 生成流程与参数（构建期一次性执行，不进 exe）

生成脚本：中间产物目录 `gen_from_source.py`（一次性工具，不属于项目源码；项目运行不依赖它）。

1. **裁切**：`Image.crop(BOX)` → 1394×1442 RGB。
2. **圆角 alpha**：以 8× 超采样（`SS=8`）绘制 `rounded_rectangle(radius=225*8)`，再 `LANCZOS` 缩回原尺寸作为蒙版，`putalpha()` 得到 RGBA。超采样是为了避免圆角边缘出现锯齿硬边。
3. **保比例贴方**（关键避坑）：1394×1442 不是正方形，**直接 resize 到 256×256 会把画面纵向压扁**（初版实测确实变形）。正确做法是先把裁切结果**居中贴到 1442×1442 的全透明画布**（左右各 24px 透明边、上下撑满），得到正方形 `base`，再等比缩放。
4. **缩放**：统一 `Image.LANCZOS`，由 `base` 一次性降到目标尺寸（不做多级降采样，避免二次模糊）。
5. **小尺寸轻度锐化**（只增强边缘对比，不改设计外观）：

   | 尺寸 | 处理 |
   | --- | --- |
   | 16px | `UnsharpMask(radius=0.5, percent=130, threshold=0)` |
   | 24px / 32px | `UnsharpMask(radius=0.5, percent=90, threshold=0)` |
   | 48px 及以上 | 不锐化（原始 `LANCZOS` 结果） |

6. **落盘**：各尺寸 PNG（`optimize=True`）+ `app.png`（= 256 档同图另存）+ 手工拼装的 `app.ico`。

> **禁止事项（红线）**：不得用生成式模型重绘、不得调色/加滤镜/加阴影、不得裁剪主体内容（如切掉挂锁或外圈）、不得为了"看起来更饱满"牺牲纵横比。图标必须与用户原图逐像素同源——校验方式就是 5.3.8 的 MAE 比对。

#### 5.3.4 ICO 容器构造（手工拼装，不用单图 `save(sizes=...)`）

`Pillow` 的 `img.save("app.ico", sizes=[...])` 只会拿一张源图内部再缩放，无法保证每档都是"该尺寸的最优渲染"。因此改为**手工写 ICO 容器**，每档塞入 5.3.2 已单独生成好的对应尺寸图：

- **结构**：`ICONDIR(6 B)` + N×`ICONDIRENTRY(16 B)` + 各档数据块，偏移量逐档累加。
- **条目**：16/24/32/48/64/128 用**32bit DIB 条目**（BITMAPINFOHEADER 40 B + 自底向上的 BGRA 像素 + 全 0 AND 掩码，`biHeight = 2×h`）；256 用 **PNG 条目**（`optimize=True` 的 PNG 字节流），兼容 Vista+ 且体积小。
- **宽度/高度字段**：256 在目录项中写 `0`（ICO 规范约定 0 表示 256），其余写实际值。
- **回读校验**：写完立刻按目录项逐档读出并与对应 `app_XX.png` 逐像素比对，实测 **7 档 MAE 全部 0.00**，证明"每档就是该尺寸图，没有二次缩放"。

#### 5.3.5 加载接线（源码，v2.5 未改动）

窗口图标走**双通道**：先 `iconbitmap(default=ico)`（`default=` 让所有 `Toplevel`/弹窗继承），失败再退 `iconphoto(True, photo)`；PNG 通道优先 Pillow、无 PIL 时退 `tk.PhotoImage`。`PhotoImage` 必须挂实例属性防 GC 空白。

```python
ICON_ICO_NAME = "app.ico"     # 多尺寸 ICO(16/24/32/48/64/128/256), 通道一首选
ICON_PNG_NAME = "app.png"     # 256px PNG, 通道二兜底

def _apply_window_icon(self):
    try:
        ico = asset_path(ICON_ICO_NAME)
        if ico:
            try:
                self.root.iconbitmap(default=ico)   # default= 让 Toplevel/弹窗继承
                self.root.iconbitmap(ico)
                return
            except Exception as e:
                self._icon_warn(f"窗口图标 ico 通道加载失败, 改用 png 兜底: {e}")
        else:
            self._icon_warn(f"图标文件不存在: assets{os.sep}{ICON_ICO_NAME}")

        png = asset_path(ICON_PNG_NAME)
        if not png:
            self._icon_warn(f"图标文件不存在: assets{os.sep}{ICON_PNG_NAME}, 窗口沿用默认图标")
            return
        photo = self._icon_via_pil(png) or self._icon_via_tk(png)
        if photo is None:
            self._icon_warn(f"窗口图标 png 通道加载失败(两条加载均不可用), 窗口沿用默认图标: {png}")
            return
        self._icon_photo = photo                 # 必须挂实例属性, 否则被 GC 后图标空白
        self.root.iconphoto(True, photo)         # True => 作为所有 Toplevel 的默认图标
    except Exception as e:                       # 最后一道防线: 图标异常不得影响主界面
        self._icon_warn(f"窗口图标加载异常, 已忽略: {e}")
```

`asset_path()` 三档兜底（v2.3 起沿用，图标与二维码共用）：

```python
def asset_path(name):
    cands = []
    meipass = getattr(sys, "_MEIPASS", None)
    if meipass:                       # ① 打包态: _MEIPASS\assets\
        cands.append(os.path.join(meipass, "assets", name))
    cands.append(os.path.join(BASE_DIR, "assets", name))       # ② exe 同级 / 源码根
    src_dir = os.path.dirname(os.path.abspath(__file__))
    if os.path.normcase(src_dir) != os.path.normcase(BASE_DIR): # ③ 源码文件所在目录
        cands.append(os.path.join(src_dir, "assets", name))
    for path in cands:
        try:
            if os.path.isfile(path):
                return path
        except Exception:
            continue
    return None
```

调用点：`__init__` 里在 `log_box` 与窗口标题设置之后调用 `self._apply_window_icon()`（源码第 360 行附近）。

#### 5.3.6 打包接线（v2.5 未改动）

exe 的**文件图标**由 spec 的 `icon=` 在构建期写入 PE，**运行时无法改**：

```python
import os
_A = os.path.abspath("assets")
_datas = []
for _n in ("sponsor_qr.png", "app.ico", "app.png"):
    _p = os.path.join(_A, _n)
    if os.path.exists(_p):
        _datas.append((_p, "assets"))

a = Analysis(["sgtunnel.py"], datas=_datas, ...)
exe = EXE(..., icon=(os.path.join(_A, "app.ico") if os.path.exists(os.path.join(_A, "app.ico")) else None))
```

- `datas` 把 `app.ico` / `app.png` 内嵌进 `_MEIPASS\assets\`，保证"只有 exe 一个文件"也能显示窗口图标。
- `icon=` 决定资源管理器里的 exe 外观；不存在时回退 `None`（PyInstaller 默认图标），不会构建失败。
- **改图标必须重打包**：只替换 `assets\` 下的文件，源码态（`python sgtunnel.py`）立即生效，但 `dist` 内 exe 的外观**不会变**。

#### 5.3.7 容错红线（v2.5 未改动）

1. 图标缺失 / 损坏 / 双通道全失败 → **只写一条日志**，窗口沿用 Tk 默认图标，**不弹窗、不抛异常、不阻塞启动**。
2. `_icon_warn()` 内部再包一层 `try`：`log_box` 尚未创建等极端时序下静默丢弃。
3. `PhotoImage`/`ImageTk.PhotoImage` 必须挂 `self._icon_photo`，否则被 GC 回收后图标变空白。
4. 图标逻辑与业务逻辑完全解耦：`_apply_window_icon()` 与本程序的隧道启停、配置读写无任何数据依赖。

## 6. V2.3 体验与健壮性优化（本轮重点）

本轮的目标是「不改布局、不改配置语义、不加依赖」的前提下，把一处一处的卡顿、误点、丢配置、静默失败修掉。逐项如下。

### 6.1 首屏延后初始化（`_deferred_init` L479）

- **问题**：`__init__` 里同步做图标解码、二维码解码、配置读取 + DPAPI 解密，窗口要等这些做完才可见（含 emoji 首帧字体回退，单这一项就 200+ ms）。
- **做法**：`__init__` 只建控件并 `after(1, self._deferred_init)`（L467）；延迟阶段按「按钮文案 → 赞助二维码 → 配置加载 → 认证方式联动」顺序执行（原先的「窗口图标」步骤已于 2026-11-06 停用并从链路中摘除），**每步独立 try**，失败只写日志不阻断；末尾在 L511 启动消息泵、L512 启动 `_tick`。
- **额外收益**：日志里会打印「首屏构建 / 按钮文案 / 含延迟初始化共」三段耗时，方便回归对比。

### 6.2 窗口居中（`_center_geometry` L470）

按 `winfo_screenwidth/screenheight` 与窗口常量（`WIN_W=640` L290、`WIN_H=820` L291）算出 `WxH+X+Y`，X/Y 用 `max(0, …)` 兜底防负数；多屏/缩放异常时退化为不带坐标的几何串。

### 6.3 日志自动跟随 + 行数上限

- `LOG_MAX_LINES = 2000`（L73）：`_log_now`（L1187）在超限时**一次裁掉超出量的 10%（至少 50 行）**，把 O(n) 裁剪摊薄，长时间运行不会内存膨胀、也不会每次插入都触发全文重排；
- 跟随模式 `_log_follow`：仅当处于跟随态且视图已在底部（`yview()[1] >= 0.999`）才 `see("end")`；用户上滚查看历史时自动暂停跟随，滚回底部恢复（`_on_log_scroll` L1217）；`_scroll_log_to_end`（L1209）用于初始化收尾强制归底。

### 6.4 四态状态文案与颜色统一

见 4.3：`STATE_STYLE` 集中定义，`_set_state_now` 一处落地「文案 + 颜色 + 按钮矩阵」。此前散落各处的 `status.config(text=…, fg=…)` 全部收口，不会再有「已停止却显示已连接」这类不同步。

### 6.5 防重复点击（`_busy` + `_refresh_buttons`）

`_enter_busy(hint)`（L1344）立即置 `_busy` 并把状态行刷成提示、同时刷新按钮；`_leave_busy()`（L1350）复位。点击「启动」后按钮组在毫秒级变灰，连点只会被忽略；所有耗时动作（端口预检、icacls、`Popen`、`terminate` 等待）都在后台线程，主线程不阻塞。

### 6.6 错误提示改为非阻塞（`_notify` L1652）

- 启动失败、解密失败等路径统一走 `_notify(title, detail, hints)`：**写日志 + 状态行变色 + 给出可操作的修复提示**，不再弹阻塞式 `messagebox`（弹窗会打断用户操作、且必须手动关闭）；
- `_fix_hints`（L1542）把常见失败（端口占用、私钥权限、认证失败、网络不可达）转成人话建议；
- 全仓已无实际 `messagebox` 调用（仅保留在 docstring 里说明「为什么不用」）。

### 6.7 配置原子写（`atomic_write_text` L114）

见 3.6。`_write_config`（L1071）先按白名单/黑名单过滤敏感键，再原子写；`_drop_password_enc`（L1004）删失效密文同样走原子写，避免「删字段时恰好断电」把整个配置写坏。

### 6.8 未保存改动追踪（`_dirty`）

- 所有输入变量挂 trace（`_on_var_edited` L1358），置 `_dirty` 后只刷新「保存配置」按钮底色（`BTN_DIRTY`，L277），**不改尺寸、不动布局**；
- `_suppress_dirty`（L310，回填守卫点 L357、L859）：程序自身回填（加载配置、面板联动）期间不计脏，避免「刚打开就提示未保存」；
- `_mark_clean`（L1366）在保存成功后清标记；
- 关窗（`_on_close` L1850）与切面板时若脏，给非阻塞提示；退出前静默保存，避免误失。

### 6.9 定时器自适应（`TICK_IDLE_MS` / `TICK_RUN_MS`）

- `_tick`（L1806）：隧道未运行时 5,000 ms 一轮且只做最轻量的状态判定；运行中 2,000 ms 一轮；
- 端口探测不在主线程做：交给 `_probe_worker`（L1823）daemon 线程，结果 `_post("probe")` → `_on_probe`（L1834）；`_probe_busy` 保证同一时刻只有一个探测在跑，`try/finally` 保证异常也会释放；
- 效果：界面空闲时几乎不耗 CPU，探测期间也不掉帧。

### 6.10 端口占用给替代端口建议（`_suggest_free_port` L1428）

启动前端口预检失败时，不再只说「端口被占用」，而是探测 `base+1 … base+30` 找到可用端口，提示「可改用 xxxxx」；本地残留 ssh 进程造成的占用在日志里会明确要求先清理。

### 6.11 本轮踩过的坑

| 坑 | 现象 | 结论 |
| --- | --- | --- |
| 延迟初始化里步骤互相连坐 | 图标失败导致配置不加载 | 每步独立 try，失败只写日志并继续 |
| 定时器里同步探测端口 | 连接慢时界面「假死」 | 探测必须进后台线程，结果回主线程 |
| `_dispatch` 调用签名不匹配 | 启动后状态不刷新、日志报「界面更新异常」 | `_on_started()` / `_on_probe(ok)` 参数要与投递一致，且异常日志带 `kind` 便于定位 |
| 上滚看日志被强行拉回 | 查历史时视图一直跳到底 | 引入 `_log_follow`，离开底部即暂停跟随 |
| 日志无限增长 | 长时间运行内存与滚动条膨胀 | `LOG_MAX_LINES` + 分 10% 批量裁剪 |
| 程序回填被当成用户编辑 | 一启动就提示未保存 | `_suppress_dirty` 守卫回填期 |
| 关窗直接 `destroy` | ssh 子进程残留 | `_on_close` 先 `_stop_worker` 回收再退出 |
| 端口占用报错太笼统 | 用户不知道怎么办 | `_suggest_free_port` 给替代端口 |

### 7.5 打包坑

- **资源改动必须重打包**：onefile exe 的资源在构建期固化，改 `assets` 内容后不重打包等于没改；
- **标题栏图标移除是运行时行为**：`_clear_titlebar_icon`（`WM_SETICON` + 全透明 HICON）不涉及资源改动；但 **exe 内嵌 `app.ico` 后 Tk 会在窗口映射完成时再设一次图标**，所以清零必须带 `WM_GETICON` 回读校验 + 400ms 重试（最多 8 次），单次清除在打包版会失效；
- **图标不要只看窗口**：窗口图标若要恢复，用的是运行时 HICON（PIL/tk 通道解码 ICO 帧），exe 文件图标来自构建期资源；比较 MAE 要用「ICO 帧 vs exe 资源」同管线比，跨管线（系统缩放渲染）在 16/48/256px 会出现 10~20 的 MAE，属正常渲染差异，不代表图标不对；
- **别把 PIL 拉进产物**：一旦业务代码顶层 `import PIL`，spec 的 `excludes` 也拦不住（会在运行期 ImportError），所以通道必须「先试 PIL、失败降级 tk」。

### 7.8 运行与部署方式

#### 7.8.1 部署全景

```
[本地 Windows]                                  [远程服务器]
 爽哥面板隧道助手.exe                             sshd : <ssh_port>
 config.json            ← 读到目标 ──────┐              │
 server_key（密钥认证时）────────────────┴── SSH 加密 ───┤ 公钥已入 authorized_keys
                                          （或密码认证     │  或 PasswordAuthentication yes
                                            运行期输入）   │
 浏览器 → https://127.0.0.1:<local_port>                  │
        → ssh.exe 监听本地端口                            │
        → 隧道 ────────────────────────────────────────→ 127.0.0.1:<remote_port>
                                                         1Panel / 雷池面板
```

v2.1 起"凭据"有两种可选形态：**私钥文件**（`auth_method: key`）或**密码**（`auth_method: password`）。v2.1 的密码完全不落盘，每次启动都要重输；**v2.2 起密码会被加密记住**——填了密码并保存，就会以 DPAPI 密文写入 `config.json` 的 `password_enc`（明文仍不落盘），下次启动自动解密回填。部署时该字段可随配置一起拷贝，但**只有原 Windows 用户在本机才能解密**，换机 / 换用户后会自动降级为"要求重新输入密码"。

#### 7.8.2 服务端前置（一次性）

| 步骤 | 操作 | 验证 |
| --- | --- | --- |
| 1. 确认 sshd 运行 | `systemctl status sshd`（或 `service ssh status`） | active (running) |
| 2. 确认 sshd 端口 | `ss -lntp \| grep sshd` 或查 `/etc/ssh/sshd_config` 的 `Port` | 与 `config.json` 的 `ssh_port` 一致 |
| 3. 准备鉴权 | **密钥**：把本地 `server_key.pub` 追加到 `~/.ssh/authorized_keys`，`chmod 600 ~/.ssh/authorized_keys`、`chmod 700 ~/.ssh`<br>**密码**：确认 `/etc/ssh/sshd_config` 里 `PasswordAuthentication yes`（含 `KbdInteractiveAuthentication` 视发行版而定），改完 `systemctl reload sshd` | 本地执行 `ssh -i server_key -p <port> root@<server>` 或 `ssh -p <port> root@<server>` 能登录 |
| 4. 确认面板仅监听回环 | 1Panel / 雷池默认监听 `127.0.0.1` 或 `0.0.0.0` | 用 `ss -lntp \| grep <remote_port>` 确认端口实际监听地址 |
| 5. 记录面板端口 | 即 `panels[].remote_port` | 与面板配置一致 |

> **关键校验在第 3 步**：本工具的隧道建立失败有 90% 源于服务端鉴权未生效或私钥权限问题。先用原生 `ssh` 手工验证通过，再回来用 GUI，可以省掉大量排查。
> 另外注意：服务器若开了 fail2ban / 云厂商的爆破防护，密码认证连续失败可能触发封 IP，而本工具设置了 `NumberOfPasswordPrompts=1`（只尝试一次，不反复重试），可降低误封风险。

#### 7.8.3 客户端部署

##### 7.8.3.1 密钥认证：三件套

```powershell
# 1) 建目录并放入三件套
New-Item -ItemType Directory -Force "D:\Tools\SGTunnel" | Out-Null
Copy-Item "E:\yscl\爽哥面板隧道助手\dist\爽哥面板隧道助手.exe" "D:\Tools\SGTunnel\"
Copy-Item "E:\yscl\爽哥面板隧道助手\server_key" "D:\Tools\SGTunnel\server_key"

# 2) 确认 OpenSSH 客户端可用
where.exe ssh        # 应输出 C:\Windows\System32\OpenSSH\ssh.exe

# 3) 启动
Start-Process "D:\Tools\SGTunnel\爽哥面板隧道助手.exe"
```

##### 7.8.3.2 密码认证：两件套（exe + config）

不需要私钥文件，把 `auth_method` 填 `password`，在界面"密码"框输入即可。密码**明文永远不写 `config.json`**；若想免去每次重输，填好密码后点一次"保存配置"，程序会用 Windows DPAPI 把密码加密成 Base64 写入 `password_enc`，此后每次启动自动解密回填密码框（日志会注明"仅当前 Windows 用户可解"）。约束三条：①换机 / 换 Windows 用户后密文失效，启动时会弹提示要求重输并自动删除失效字段；②想把密码彻底从磁盘抹掉，清空密码框再保存，`password_enc` 会被整条删除；③同一会话内点"重新加载"会按新配置重填密码框。

##### 7.8.3.3 首次运行的真实行为（v2.1 已变更）

> **v2.1 不再生成默认模板配置**。首次运行（同目录没有 `config.json`）时：窗口打开、所有输入框**全部空白**、日志区提示"未找到 config.json, 界面保持空白, 点保存配置后将生成"。手动填写后点"保存配置"才会落盘生成文件。

这与 v2.0 的行为不同（v2.0 会自动写一份含 `22022`/`root`/`server_key`/`40001`/`16002` 的模板）。改动理由是"空即空"原则：任何默认值都可能让用户误以为配置已就绪，或在换服务器时把旧模板值带进生产配置。

> **不要**把程序放进 `C:\Program Files` 之类受保护目录：`save_config` 需要对 `config.json` 有写权限，UAC 虚拟化会导致"保存成功但实际没写进去"的假象。

#### 7.8.4 标准使用流程

1. 双击 exe → 窗口打开，若已有 `config.json` 自动加载（空字段保持空白）。
2. （首次）填写：服务器 IP、SSH 端口、用户名 → 选认证方式：
   - **密钥认证**：填密钥文件名 `server_key`（程序目录内可只写文件名）；启动时程序自动 `icacls` 收紧权限。
   - **密码认证**：密钥框自动禁用，在密码框输入（掩码显示）。密码只在内存中使用；若希望下次启动免输，勾选/直接保存即可（见 5.3.4）。
3. 下拉选择目标面板 → 本地/远程端口自动联动。
4. 点"保存配置" → 其它字段落盘，**密码以 DPAPI 密文写入 `password_enc`**（密码框为空则删除该字段）；提示框会明示"密文已保存 / 密文已删除"。需要时可点"重新加载"确认读回一致（密码会自动回填）。
5. 点"启动隧道" → 参数校验通过后状态由黄字"启动中..."变绿字"已连接 ✅"。
6. 点"打开面板" → 默认浏览器打开 `https://127.0.0.1:<本地端口>`。
7. 用完后点"停止隧道"，或直接关窗 —— **v2.1 关窗会显式清理**：`WM_DELETE_WINDOW` 触发 `_on_close`，先 `terminate()`（3 秒超时则 `kill()`）结束 `ssh.exe`，再清空内存密码、删除 askpass 临时目录，最后 `destroy()`，不再依赖"管道断裂后 ssh 自行退出"。

> 若点"启动隧道"时弹出"配置无效"聚合框，按提示逐条修（如"SSH 端口无效: 'abc'(需为 1-65535 的整数)"），修完再启动。v2.1 把原先"静默失败"的脏值路径全部前移成了可见报错。

#### 7.8.5 源码方式运行

```powershell
cd E:\yscl\爽哥面板隧道助手
python sgtunnel.py
```

两种运行方式的差异（这是排查"配置读了但值不对"的核心）：

| 维度 | exe（冻结态） | 源码态 |
| --- | --- | --- |
| `sys.frozen` | `True` | 不存在 → `getattr` 返回 `None`，走 else 分支 |
| `BASE_DIR` | `os.path.dirname(sys.executable)` = exe 所在目录 | `os.path.dirname(os.path.abspath(__file__))` = 脚本所在目录 |
| `CONFIG_PATH` | `<exe目录>\config.json` | `<脚本目录>\config.json` |
| 相对 `key_path` 解析基准 | exe 目录 | 脚本目录 |
| askpass 临时目录 | `%TEMP%\sgtunnel_askpass_*`（两种方式相同） | 同左 |

> 因为两种方式都定位到"程序文件所在目录"，**同一个项目目录里既跑源码又跑 dist exe 时，它们读的是两份不同的 config.json**（根目录一份、`dist` 一份）。排查时务必确认当前程序读的是哪一个 —— 保存成功后弹框会显示完整路径，可用它来确认。

#### 7.8.6 日常运维

| 场景 | 操作 |
| --- | --- |
| 换服务器 | 改 `server` / `ssh_port` / `user` / 换凭据（密钥文件或密码）→ 保存 → 重启隧道 |
| 新增面板 | 编辑 `config.json` 加一项 → 点"重新加载" → 选择即可 |
| 隧道突然断开 | 看日志最后几行 `ssh:` 原文；常见是网络切换、服务端重启、空闲超时（`ServerAliveInterval=30` 已缓解） |
| 换机器 / 换目录 | 整个目录拷贝，`key_path` 保持裸文件名 `server_key` 即可（保存时会自动轻量化） |
| 私钥权限报错 | 程序已自动 `icacls`；仍失败则手动执行 `icacls server_key /inheritance:r /grant:r "%USERNAME%:(R)"` |
| 本地端口冲突 | 改该面板的 `local_port`（仅左侧变化，`remote_port` 保持面板真实端口） |
| 密码认证失败 | 依次查：`ssh -V` 是否 ≥ 8.4（`SSH_ASKPASS_REQUIRE` 支持）、服务端 `PasswordAuthentication`、`powershell` 是否可用（askpass 脚本依赖它做 UTF-8 输出）、密码是否含 `"`/`&`/`!` 等字符（已兼容，若仍异常可先改成简单密码验证链路是否通） |
| 想确认密码没落盘 | 打开 `config.json` 检查：应无任何 `password`/`passwd`/`pwd` 字段；密码若被记住，只会以 `password_enc`（Base64 密文）形式存在（v2.2） |
| 想清掉已记住的密码 | 清空密码框 → 点"保存配置"，`password_enc` 整条删除（提示框会显示"已清除密码密文"）；或直接手工删掉该字段后点"重新加载" |
| 提示"密码需要重新输入" | 换机 / 换 Windows 用户 / 密文损坏都会导致 DPAPI 解密失败（预期行为）：密码框留空、失效字段已自动删除，重输密码并保存即可重新记住 |
| 清理残留 | `%TEMP%\sgtunnel_askpass_*` 目录（内含脚本模板、无密码）可随时全删；`ssh.exe` 残留用任务管理器结束 |

#### 7.8.7 卸载与回滚

程序**不写注册表、不建服务、不写系统目录、不产生用户态缓存**（除 PyInstaller 运行时的 `%TEMP%\_MEIxxxx` 临时解压目录，退出即清理）。卸载 = 删除存放 exe/config/key 的目录。

> DPAPI 密文（`password_enc`）**不写入任何系统级存储**，只存在于 `config.json` 里，随文件删除即消失；删掉 `config.json` 或 `password_enc` 字段后，Windows 侧不残留可解密副本（DPAPI 只是用当前用户主密钥加解密，不保存应用数据副本）。

| 配置项 | 回滚影响 |

| `key_path`（裸文件名） | 完全兼容，v2.0 也有同样的 `BASE_DIR` 拼接逻辑 |
| `panels[]` | 完全兼容 |

### 7.9 两份 spec 逐项差异详表

项目根目录存在两份 PyInstaller 构建脚本，内容逐行对比后结论是：**除 `name` 字段外完全一致**（v2.3 起两份的 `datas` / `excludes` 同步更新）。

| 项目 | `SGTunnel.spec` | `爽哥面板隧道助手.spec` |
| --- | --- | --- |
| 入口脚本 | `sgtunnel.py` | `sgtunnel.py` |
| `name`（输出名） | `SGTunnel` | `爽哥面板隧道助手` |
| `datas` | `[(assets\sponsor_qr.png, 'assets'), (assets\app.ico, 'assets'), (assets\app.png, 'assets')]`（v2.4 起，v2.5 未变；逐个动态探测，任一不存在则跳过该项，全不存在回退 `[]`） | 同左 |
| `icon`（v2.4 新增，v2.5 未变） | `assets\app.ico`（不存在则 `None`，回落 PyInstaller 默认图标） | 同左 |
| `binaries` | `[]` | `[]` |
| `hiddenimports` | `[]` | `[]` |
| `excludes` | `['PIL','PIL.Image','PIL.ImageTk','numpy']`（v2.3，保零依赖） | 同左 |
| `console` | `False` | `False` |
| `upx` | `True` | `True` |
| `debug` | `False` | `False` |
| 构建模式 | onefile（`EXE` 直接消费 `a.binaries`/`a.datas`，无 `COLLECT`） | 同左 |
| 文件体积 | 1,405 B | 1,421 B（差的 16 字节即中文名多出的 UTF-8 字节） |

**`datas` / `icon` 写法（v2.4，两份一致）**：

```python
_spec_dir = globals().get("SPECPATH") or os.getcwd()
_datas = []
for _name in ("sponsor_qr.png", "app.ico", "app.png"):
    _src = os.path.join(_spec_dir, "assets", _name)
    if os.path.isfile(_src):
        _datas.append((_src, "assets"))     # 源路径 → 包内目录 assets/

_icon = os.path.join(_spec_dir, "assets", "app.ico")
if not os.path.isfile(_icon):
    _icon = None                            # 图标缺失也能构建, 只是 exe 用默认图标
```

- 用 `SPECPATH` 定位 spec 所在目录，**不受执行 `pyinstaller` 时的当前工作目录影响**。
- 文件缺席时不报错，自动降级（缺图缺 ICO 都能构建成功，只是对应外观退化）。
- 包内目标目录必须叫 `assets`，与 `asset_path` 第一档 `<_MEIPASS>/assets/<name>` 严格对应。
- `icon=` 只影响 **exe 文件图标**（PE 资源），与运行时 `iconbitmap` 读的 `_MEIPASS\assets\app.ico` 是两条独立链路；两者都源于同一个 `assets\app.ico`，但**必须重新打包才会让文件图标更新**。
- `excludes` 排除 `PIL` 系列与 `numpy`：即使构建机装了 Pillow，也**不会**把 PIL 打进 exe——这是"零第三方依赖"红线的强制保障（源码里 PIL 只在函数内 `try import`，被排除后自动走 tk 通道）。（v2.4 补充：图标 PNG 通道同样遵守此约束，PIL 被排除时改用 `tk.PhotoImage`。）

**以哪份为准**：以 `爽哥面板隧道助手.spec` 为准，因为 `dist` 内实际产物是 `爽哥面板隧道助手.exe`，对外分发名也是中文名。`SGTunnel.spec` 是英文 slug 时期的历史遗留，保留可作回退（英文名在部分命令行/脚本环境下更省事）。

> **维护建议**：两份 spec 并存会造成"改一份忘另一份"的漂移。合理处置是**只保留中文名 spec**，把英文名需求改为构建后重命名，或直接删除 `SGTunnel.spec`。若保留双份，任何参数调整（如加 `version` 文件、加图标）必须同时改两处。

### 7.10 spec 关键参数含义

| 参数 | 取值 | 含义与影响 |
| --- | --- | --- |
| onefile 模式 | 无 `COLLECT` 段 | 最终只产出一个 exe；运行时解压到 `%TEMP%\_MEIxxxx`。启动比 onedir 略慢（解压开销），但分发只需一个文件 |
| `console=False` | 关 | 不分配控制台窗口，GUI 程序必需；副作用：`print`/未捕获异常无可见输出（`disable_windowed_traceback=False` 时 PyInstaller 会尝试弹错误框） |
| `upx=True` | 开 | 有 UPX 时压缩二进制段。未安装 UPX 时 PyInstaller 只告警"UPX is not available"并跳过，**不失败** |
| `debug=False` | 关 | 不输出 bootloader 调试信息 |
| `strip=False` | 关 | Windows 下无实际意义（主要针对 Unix） |
| `optimize=0` | 0 | 不做字节码优化，保留断言与 docstring |
| `noarchive=False` | 关 | 标准 PYZ 归档，源码打包进 `base_library.zip`/PYZ 而非散落 |
| `datas`（v2.3 起非空，v2.4 扩项） | `sponsor_qr.png` + `app.ico` + `app.png` | 入包资源共三项：赞助二维码 + 图标 ICO + 图标 PNG，均解包到 `_MEIPASS\assets\`，运行时由 `asset_path` 第一档命中。**`config.json` / `server_key` 仍不在 `datas` 中**，所以"配置与私钥必须外置"的设计前提不变 |
| `excludes`（v2.3 起非空） | `PIL` / `PIL.Image` / `PIL.ImageTk` / `numpy` | 显式排除可选增强依赖，保证 exe 体积与"零第三方依赖"承诺不受构建机环境影响 |
| 无 `version=` | — | exe 无文件版本/产品版本/公司名/描述资源。实测 `VersionInfo` 四项全空，右键属性"详细信息"页除大小外基本空白（版本只能靠窗口标题的 `APP_VER` 识别） |
| `icon=`（v2.4 起非空） | `assets\app.ico` | 构建期把 7 档 ICO 写进 PE 资源，资源管理器/任务栏/快捷方式显示盾牌图标。改图标 = 改 `assets\app.ico` + 重新打包；运行期不读这个资源 |

#### 8.1.1 代码层：高危（会抛未捕获异常或功能静默失效）

##### 8.1.1.1 端口非数字 → 监控线程静默死亡 ✅ 已修复（v2.1）

- **原现象**：把本地端口改成 `abc` 或留空后点启动，隧道实际能起来（或 ssh 报错），但日志不再更新、状态长期停在"启动中"；点"打开面板"弹 Python traceback。
- **原根因**：`_monitor` 里 `self.port_open(port=int(self._lport))`、`open_panel` 里同样在调用外层 `int()`，而 `port_open` 内部虽有容错，异常在进入函数之前就已抛出，daemon 线程直接终止。
- **v2.1 修复**：
  1. 新增 `_parse_port()` 静态方法：非数字 / 空 / 越界一律返回 `None`，绝不抛异常；
  2. `port_open`、`_monitor`、`_tick`、`open_panel` 全部改用 `_parse_port` 并显式处理 `None`；
  3. `start_tunnel` 前置 `_validate()` 直接拦截非法端口，弹框明示"本地端口无效: 'xxx'(需为 1-65535 的整数)"；
  4. `_monitor` 阶段1 若 `lport is None`，写日志"⚠ 本地端口无效，无法探测就绪状态"后**继续转发 ssh 输出**，不再静默死亡。
- **回归检查**：把本地端口填 `abc` 点启动 → 应立即弹"配置无效"聚合框，且状态不进入"启动中"。

##### 8.1.1.2 `stop_tunnel` 的 `wait` 超时未捕获 ✅ 已修复（v2.1）

- **原现象**：极端情况下点"停止隧道"，界面弹 `subprocess.TimeoutExpired` traceback。
- **原根因**：`wait(timeout=5)` 不在 try 内；`kill()` 兜底只挂在对 `terminate()` 的 except 上。
- **v2.1 修复**：完整三级兜底 —— `terminate()` → `wait(5)`，`TimeoutExpired` 时日志"ssh 未在 5 秒内退出, 强制结束" + `kill()` → `wait(3)`，仍超时则提示"请在任务管理器中结束残留的 ssh.exe"。所有分支都保证 `proc=None`、按钮态与状态文案落到"已停止"。
- **回归检查**：用一个假的 `Popen`（`wait` 抛 `TimeoutExpired`、`kill` 打标记）替换 `app.proc` 后调 `stop_tunnel()`，应无异常抛出、日志含"强制结束"、状态为"● 隧道已停止"（本项已按此方式实测通过）。

##### 8.1.1.3 后台线程直接操作 Tk 控件 ✅ 已修复（v2.1）

- **原现象**：高频 ssh 输出或关窗瞬间偶发 `TclError: invalid command name` / 界面短暂无响应。
- **原根因**：`_monitor`（daemon 线程）直接调用 `self.log()` / `self.set_status()` 改控件。
- **v2.1 修复**：引入 `queue.Queue` + `root.after(100, _drain_ui)`。`_monitor` 只通过 `_post(kind, *args)` 入队三种消息（`log` / `status` / `exited`）；`_drain_ui` 在主线程出队并调 `_log_now` / `_set_status_now` / `_proc_exit`。`log()` 与 `set_status()` 保留"主线程直写、后台线程入队"的双模入口，调用方无需感知线程身份。
- **回归检查**：全局搜索 `self.log(` / `self.set_status(` 在 `_monitor` 内的用法，应全部是经 `_post` 的间接调用；`_proc_exit` 只允许由 `_drain_ui` 或 `_tick`（均为主线程）触发。

##### 8.1.1.4 `readline()` 阻塞导致退出检测延迟 🔶 已缓解

- **现象**：ssh 进程已退出，但"已断开"状态可能要等 `_tick` 的下一个 2 秒周期才翻转。
- **现状**：阶段2 改为 `for line in iter(proc.stdout.readline, "")`，stdout 关闭时迭代自然结束并投递 `exited`，比 v2.0 的 `while True: readline()` 更快感知；但 ssh 静默期间该调用仍阻塞，`_tick` 依旧是退出检测的实际主力。
- **规避**：正常表现可接受（最长 2s 延迟）。**不要**为此删掉 `_tick`。
- **彻底修复方向**：把读 stdout 拆成独立线程（读线程只入队，主线程按队列活跃度判断），或改用 `select`/`pywin32` 管道监听。属 P1（见 9.2）。

#### 8.1.2 代码层：中低危（体验与安全）

##### 8.1.2.1 关闭主机密钥校验 ⚠️ 仍存在

`StrictHostKeyChecking=no` 关闭了中间人防护。首次连接任意主机都自动接受其公钥，若 DNS/网络被劫持，可能连到伪造服务器。密码认证下该风险**显著放大**（v2.1 新增能力，会把口令交给对方而不是只做签名）。
**建议**：内网自用可接受；要加固则改 `StrictHostKeyChecking=accept-new`，或提供 `known_hosts` 指纹固定入口（9.3 第 18 项）。

##### 8.1.2.2 只支持私钥认证 ✅ 已修复（v2.1）

v2.0 无密码/键盘交互认证路径，服务端只开密码认证时工具不可用。v2.1 新增"密码认证"单选，经 `SSH_ASKPASS` 递交口令（机制详见 5.3.3）；v2.2 起密码可用 DPAPI 加密持久化到 `password_enc`（详见 5.3.4）。明文不落盘、不进命令行。残留约束：

- 依赖 OpenSSH 8.4+（`SSH_ASKPASS_REQUIRE=force`），本机 9.5p2 满足；老版本需升级或改用密钥；
- 依赖 `powershell` 可执行（askpass 脚本用它做 UTF-8 输出来兼容中文与特殊字符）；`powershell` 被策略禁用时会退回 `cmd` 延迟展开路径，中文密码可能乱码；
- 不支持"密钥 + 二次口令"的复合场景（`PubkeyAuthentication=no` 会跳过公钥）。

##### 8.1.2.3 `open_panel` 硬编码 `https` ⚠️ 仍存在

`url = f"https://127.0.0.1:{lport}"` —— 若某面板只跑 HTTP（如自建 Grafana 未开 TLS），打开即报 TLS 错误。**规避**：手动在浏览器改 `http://`。修复方向见 9.2 第 12 项（`panels[].scheme`）。

##### 8.1.2.4 日志不落盘 ⚠️ 仍存在

ssh 输出只在界面上，关窗即失。隧道问题往往发生在"用户点完就去干别的"之后，回来时日志已被顶掉或窗口已关。**建议**：加 `logging` + `RotatingFileHandler` 写 `BASE_DIR/sgtunnel.log`（1MB × 3）。注意打包后需确认目录可写。

##### 8.1.2.5 无单实例保护 ⚠️ 仍存在

可同时开多个窗口，多个 ssh 抢同一 `local_port`，后启动者因 `ExitOnForwardFailure=yes` 立即退出。v2.1 的端口占用预检能提前给出"已被占用"提示，但拦不住"两个实例各用不同面板却抢同一端口"这类配置错误。**规避**：自己注意只开一个。

##### 8.1.2.6 面板无增删 UI / 不能改名 ⚠️ 仍存在

增删面板只能手改 JSON。`_resolve_panel_name` 仍保留对旧式 `名字 (端口)` 标签的解析（`startswith(name + " (")`），若面板名本身含 ` (` 会造成匹配歧义。v2.1 增加的是**读取侧去重**（同名自动加 `-2` 后缀），不是 UI 编辑能力。

##### 8.1.2.7 关窗不显式回收 ssh ✅ 已修复（v2.1）

新增 `root.protocol("WM_DELETE_WINDOW", self._on_close)`：关窗前 `terminate()` → `wait(3)` → 超时 `kill()`，并清空 `_password`、删除 askpass 临时目录，最后 `destroy()`。

##### 8.1.2.8 密码保护的强度边界 🔶 已改善（v2.2 DPAPI），仍非凭据管理器级

v2.1 的密码不落盘、不进命令行，但确实存在于 `ssh.exe` 子进程的环境变量 `SG_TUNNEL_PW` 中，并在整个隧道生命周期内保持（askpass 可能被再次调用）。

v2.2 引入 DPAPI 后，"持久化"这一段被补上且加密，风险面变化：

| 攻击场景 | v2.1 | v2.2 |
| --- | --- | --- |
| 配置文件被拷走 / 上传网盘 / 贴群聊 | 无密码可泄露（密码根本没存） | 只有密文，**离开本用户无法解密** |
| 同机其他 Windows 用户读到 `config.json` | 无影响 | 密文对其无效（DPAPI 密钥按用户隔离） |
| 本机同用户的其他程序读到 `config.json` | 无影响 | ⚠️ 该程序若以同用户身份运行，可调 `CryptUnprotectData` 解出明文 —— **这是 DPAPI 用户级的固有限制** |
| 攻击者已获得该用户登录态 | 需内存抓取 | 需内存抓取或直接解密 |
| 进程环境变量读取 | 需 `PROCESS_VM_READ` | 同 v2.1，未改变 |
| 内存转储（dump） | 可读出明文 | 同 v2.1，未改变（DPAPI 只在写盘/读盘瞬间生效） |

**结论**：v2.2 把"配置泄露即密码泄露"这条风险降到"配置泄露 + 同用户代码执行才泄露"，对单人自用内网工具足够；但它不是凭据管理器（无 TPM/生物识别/主密钥额外口令），若要做多人共用或面向公网的分发工具，应改为 `CredWrite` / Windows 凭据管理器存储，并接受随之而来的 Windows 专用依赖（见 9.3 第 15 项，v2.2 已用 ctypes 部分兑现）。

**换机/换用户后的表现（预期行为，不是缺陷）**：解密失败 → 密码框留空 + 提示"密码需要重新输入" + 删除失效密文，其它配置照常可用。

#### 8.1.5 安全层

| 风险 | 说明 | 处置 |
| --- | --- | --- |
| `dist` 内含私钥副本 | `dist\server_key` 与源密钥哈希一致，等于"凭据包" | 外发前删除；版本库忽略 `dist/` 与 `server_key` |
| 配置含真实服务器地址 | `config.json` / `dist/config.json` 均有真实 IP | 分享截图/配置前打码或替换 |
| 密码存在于进程环境变量 | 见 8.1.2.8 | 可接受；读取需 `PROCESS_VM_READ`，普通同级进程拿不到；不外发 `%TEMP%\sgtunnel_askpass_*` 残留目录（其中无密码，仅脚本） |
| 配置中存在 `password_enc` 密文 | DPAPI 用户级密文，绑定当前 Windows 账户 | 可安全随配置备份/拷贝；**换机或换用户后失效**（预期行为，会提示重输）；仍不建议把 `config.json` 公开分享（含真实 IP 与密文） |
| 同用户进程可解密 `password_enc` | DPAPI 用户级固有限制，见 8.1.2.8 | 接受；若需更强保护改用 Windows 凭据管理器（9.3 第 15 项） |
| askpass 临时目录残留 | 程序崩溃时不执行清理 | 内容只有 `.cmd` 脚本模板，不含密码；可手工删 `%TEMP%\sgtunnel_askpass_*` |
| 私钥权限自动收紧 | `icacls /grant:r <user>:(R)` 只授读权限，是收紧操作 | 无需处理；注意 `USERNAME` 为空时回退 `Administrator`，若当前用户不是该名则授权对象错误，日志会显示失败 |
| 日志含私钥路径 | 日志行会打印完整 `-i <路径>`（仅密钥认证） | 属路径非内容，可接受；外发日志时注意路径暴露目录结构 |
| 配置中残留明文密码 | v2.1 读取时忽略并提示，不加载、不回写 | 仍建议手工删掉该字段，避免误解 |

#### 8.1.6 使用层常见误判

| 现象 | 常被误判为 | 真实原因 |
| --- | --- | --- |
| 状态绿了但浏览器打不开面板 | 隧道坏了 | 面板服务本身没起，或 `remote_port` 填错（隧道通 ≠ 远端服务在监听，`-L` 只在连接时才去连远端） |
| 换网络后隧道"假活" | 程序 bug | `port_open` 探的是本地监听端口，本地端口一直由 ssh 占着，即使链路已断也返回 True。需靠 `ServerAliveInterval` 让 ssh 自行退出后才发现 |
| 密码认证一直失败、日志无内容 | 程序没传密码 | 先看 `ssh -V` 是否 ≥ 8.4（`SSH_ASKPASS_REQUIRE` 支持）；再确认服务端 `PasswordAuthentication yes`；最后确认 `powershell` 未被策略禁用 |
| 密码认证填了密钥但没生效 | 二选一不生效 | 认证方式是单选，选了"密码认证"时 `-i` 不会拼入命令，密钥框也被禁用 —— 这是设计而非缺陷 |
| 面板登录后一直 403/跨域 | 隧道问题 | 1Panel/雷池有域名白名单或安全入口校验，需在面板侧放行 `127.0.0.1` |
| 浏览器提示证书不安全 | 工具问题 | 面板自签证书 or 证书域名与 `127.0.0.1` 不符，属预期 |
| 首次运行界面全空 | 程序坏了 | v2.1 取消了默认模板，空配置即空界面（见 4.5 节） |

## 9. 已知限制与待办

- 仅支持 Windows（DPAPI / icacls / SSH_ASKPASS 均依赖 Windows 行为）；
- 单条隧道单实例：同一时刻只维护一条 ssh 转发；
- 面板数量无上限校验，配置里 `panels` 写得过多时下拉框会很长（不影响功能）；
- 待办：图标多档位渲染一致性（16/48/256px 跨管线偏差）可考虑按档位单独出图；
- 待办：日志落盘（当前仅内存 + 界面），排障需用户手动复制。

#### 9.1.4 不建议做的事

| 事项 | 原因 |
| --- | --- |
| 把 `config.json` 打进 exe（回到 `datas`） | 破坏"配置可改可存"的核心设计 |
| 把 `server_key` 打进 exe | 凭据固化进可分发二进制，等同于泄露 |
| **把密码明文存进 `config.json`** | 读配置时忽略并提示、保存时无条件剔除。v2.2 起"记住密码"需求统一走 `password_enc`（DPAPI 密文），而非明文或裸 Base64 |
| **用自写弱加密冒充加密** | 裸 Base64、固定密钥异或、硬编码盐值都等同于明文；必须由系统密钥（DPAPI）保护 |
| 把密码拼进 `ssh` 命令行（伪 `-o` 或 `sshpass` 类方案） | 命令行可被任务管理器/审计工具读取，等同明文暴露；Windows 下也没有可靠的 `sshpass` 等价物 |
| 为跨平台而抽象 `icacls` / askpass | 当前只在 Windows 发布，过度抽象增加维护成本；真要跨平台时再抽策略接口 |
| 加自动更新 | 单人自用工具，收益低于维护成本；版本靠文件名标注即可 |

### 10.9 配置兼容规则与凭据红线

1. **只增不改不删**：新增字段必须提供缺省回退；不得重命名或删除既有字段。若必须变更结构，走"读旧→转换→写新"的迁移函数，并保留 `isinstance` 探测式兼容分支的等价逻辑。
2. **`panels` 结构冻结**：`name` / `local_port` / `remote_port` 三字段的语义与类型不得变化。可新增可选字段（如 `scheme`），读取侧必须对缺失字段显式回退。
3. **`name` 是主键**：任何涉及面板定位的逻辑都必须用 `name` 精确匹配；新增面板时必须校验唯一性（读取侧已有自动去重，写入侧仍需注意）。
4. **端口一律字符串**：JSON 读写保持 string，不改成 number（避免 `null` → `"None"` 类脏值）。
5. **空即空（v2.1 新增硬约束）**：`load_config` 不得为任何"值型字段"注入默认值。空字符串、`null`、字段缺失一律映射为空白输入框。唯一的例外是 `auth_method`（模式选择，缺省 `key`）与 `current`（选择行为，缺省取首个面板）。
6. **禁止删除旧字段兼容分支**：只要还有 v1.x / v2.0 配置在用，`load_config` 的回退分支就必须保留；删除前先确认无历史配置。
7. **旧配置永不崩**：任何配置改动后，都要用"删掉 `panels` 的 v1.x 配置"和"无 `auth_method` 的 v2.0 配置"各跑一遍启动验证。
8. **`password_enc` 是可选字段（v2.2）**：缺失不得报错；解密失败必须降级为"密码框留空 + 提示 + 删除字段"，且**不影响其它任何字段的加载**。禁止把它改成必填、禁止在其中夹带明文。
